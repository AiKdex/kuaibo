主题交付五大避坑清单
每一处都不会让构建报错

这份清单来自 EmForum 主题 v1.1.0 的真实代码审查。以下 5 个问题有共同特征： 构建全部通过、控制台干干净净、代码看着完全正常 —— 只有真正点进去用，才会发现出了问题。

来源 EmForum v1.1.0 审查实录 二次验证 brutal / parchment 主题 配套工具 theme-lint.sh 日期 2026-09-15 规范同步 v1.3 · 2026-09-17（新增平台能力边界 2 项检查）

五个问题 · 逐条对照

1

页内锚点写进了 hash

宿主是 hash 路由（#/blog?view=public），锚点等于篡改路由状态

功能隐患
✕ 错误写法
<a v-for="y in years" :key="y"
   :href="'#y-' + y">
  {{ y }} 年
</a>

<section :id="'y-' + y">…</section>
✓ 正确写法
<button v-for="y in years" :key="y"
        type="button"
        @click="jumpTo(y)">
  {{ y }} 年
</button>

function jumpTo(y) {
  const el = document.getElementById('y-' + y)
  if (el) el.scrollIntoView({behavior:'smooth'})
}
为什么危险：点击后地址栏变成 /app#y-2026，路由匹配不到这个路径 → 可能跳 404、白屏，或与 Vue Router 的滚动管理互相打架。 而且开发阶段几乎发现不了 —— 它只在真实地址栏环境（非 iframe 预览）下才复现。 注意两种写法都要查：href="#x" 和 :href="'#' + x"。
2

文案说「热门」，数据其实是「最新」

承诺了契约里根本不存在的能力

语义失真
✕ 错误写法
{{ searched
   ? `关键词「${keyword}」的搜索结果`
   : '热门文章' }}

// 实际渲染：按 updated_at 倒序的前 8 篇
// 「热门」需要 浏览量/点赞/评论数
// 而契约里没有这些字段
✓ 正确写法
{{ searched
   ? `关键词「${keyword}」的搜索结果`
   : '最新更新 · 输入关键词开始检索' }}

// 标题描述真实数据 + 给出行动指引
为什么严重：用户点进「热门」看到最新文章，会直接认为站点排序坏了或数据造假。 规则：文案里每个形容词都要能被真实字段证明。高危词：热门、排行、热搜、精选、浏览量、点赞、阅读时长、评论数、封面图 —— 契约里全部不存在。

一个例外：file.author 属系统侧待透出字段（规范 §10-10），允许使用，但必须可选链降级 —— 「可能为空」和「不存在」是两回事。
3

类名与配色在暗示「排名」

实现只是按时间取前 5，命名和视觉却在宣称热度

语义失真
✕ 错误写法
<ul class="ef-hot">
  <span class="ef-rank">{{ i+1 }}</span>
  <a class="ef-hot-t">…</a>
</ul>

/* 前三名红/金/青「榜单色」 */
.ef-hot li:nth-child(1) .ef-rank{color:var(--th-hot)}
.ef-hot li:nth-child(2) .ef-rank{color:var(--th-gold)}
.ef-hot li:nth-child(3) .ef-rank{color:var(--th-jade)}
✓ 正确写法
<ul class="ef-latest">
  <span class="ef-latest-no">{{ i+1 }}</span>
  <a class="ef-latest-t">…</a>
</ul>

/* 序号统一弱化，不做名次区分 */
.ef-latest-no{color:#c3ccd8}
为什么隐蔽：类名是写给维护者的契约（半年后有人读 ef-hot，会以为这里有热度计算逻辑，改需求时按错的心智动手）； 配色是写给读者的语义（红/金/青前三名 = 排行榜的通用视觉语言）。 两者叠加，等于在代码和界面里同时植入一个不存在的功能。

规则：命名描述事实，不描述期望。时间序用 latest / recent，人工置顶用 pinned，别用 hot / rank / trending。 同理，版面文案里「头条」（描述位置，可证）安全，「精选」（描述品质，不可证）危险。
4

manifest.tokens 漏报令牌

CSS 定义了 15 个，台账只声明了 11 个

规范偏差
✕ 错误状态
// style.css 实际定义：
--th-accent-soft
--th-accent-2-soft
--th-navy-2
--th-hot          ← 定义了

// manifest.js tokens 里：
（以上 4 个全部漏报）
✓ 正确做法
tokens: {
  '--th-ink': '正文色（深蓝灰）',
  '--th-accent-soft': '强调色极浅底',
  '--th-accent-2-soft': '点缀色半透明底',
  '--th-navy-2': '头部渐变中间色',
  '--th-hot': '警示色',
  …
}
// 与 style.css 逐项一致
为什么必须用工具卡：tokens 是主题的令牌台账（后台据此生成可编辑项、文档自动生成、跨主题比对）。 但它是结构性遗忘 —— 随手加一条 CSS 变量，往往忘了回填 manifest。 证据：在产主题 brutal 也漏了 5 个（--th-bw / --th-bw-2 / --th-sh / --th-sh-lg / --th-sh-sm），parchment 同样有过。这不是谁不够细心。
5

悬空类：模板有类名，CSS 没规则

样式静默失效，靠继承「碰巧」看起来正常

规范偏差
✕ 错误状态
<aside class="ef-side">   ← 用了
<span class="ef-feed">    ← 用了

/* style.css 里： */
（两者都没有任何规则）
✓ 正确做法
/* 补齐最小必要规则 */
.ef-feed{
  font-weight:700;
  color:var(--th-ink-2);
  letter-spacing:.5px;
}
.ef-side{min-width:0}  /* 防 grid 子项被撑破 */
为什么不只是「少写一条样式」：它意味着你写下的结构意图没有被样式兑现。 当前看着正常，只是因为父容器的字号颜色恰好被继承下来 —— 父级一动，这里就毫无征兆地塌掉，而排查时没人会想到一个「看起来有样式」的类根本没规则。

顺带一个高频疏漏：grid 子项忘记 min-width: 0，长标题和输入框会直接把列宽撑破（brutal 的 .bt-hero-main 就是这情况）。

自查脚本 · 提交前跑一遍

随包提供 tools/theme-lint.sh，复制到主题目录运行即可。v1.3 起 8 项检查：类名交叉比对、令牌台账、hash 锚点、高危文案词、契约外字段、文章页视图隔离、自建密码框/解锁逻辑（新）、!important 用量（新）。
v1.3 修正：宿主为 hash 路由，# /blog/tag/… 等内页路由链接是合法写法，锚点检查已排除 # / 开头的 hash，只报锚点型（如 href="#y-2026"）。平台新能力（密码锁 / 置顶排序 / 阅读量 / 评论）的边界约定见规范 v1.3 §7.4。
cd web/src/themes/<id>
bash theme-lint.sh          # 类名前缀自动推断
bash theme-lint.sh bt-      # 或显式指定
echo $?                     # 0 = 通过；1 = 存在必修项

脚本也有盲区，命中 [!] 时务必人工确认： 动态拼接的类名（如 'bt-pat-' + name）静态扫描看不到，会被误报成死 CSS； 类名前缀自动推断可能取错；只扫 .vue，辅助 JS 里的类名不在范围。

值得说明的是，脚本自己也踩过两个坑并已修正： 初版把「解释『不要这样写』的注释」判成违规（已加注释剔除）； 正则用 awk -v 传参导致反斜杠被吞、\.cover 退化成 .cover，把 bt-cover 误报为契约外字段（已改用 ENVIRON）。

提交前自检清单

构建与协议

  • npm run build 零错误零警告
  • console 无「主题缺少 entry/id」
  • 入口组件内 import './style.css'
  • 选择器全部挂 .xx-root
  • tokens 与 CSS 实际令牌逐项一致

数据契约

  • 数据全部 inject('themeContext')
  • 只用 token/path/preview/created_at/file.*
  • 不臆造 views/likes/comments/cover/readTime
  • 不自行重排 posts
  • 三态齐全：loading / error / 空态
  • 首篇不重复

文案与语义

  • 每个形容词都能被真实字段证明
  • 类名描述事实，不描述期望
  • 榜单配色仅在真有排名数据时使用
  • 标签云空时隐藏，非链接输出
  • 站名用 <div>，不占 <h1>

交互 · 样式 · 接入

  • 全站无把锚点写进 hash 的写法
  • 页内跳转用 scrollIntoView()
  • 文章点击走 ctx.postUrl() 跳 SSR
  • 无悬空类、无死 CSS
  • grid 子项加 min-width: 0
  • 已加 BlogView import 与白名单
  • 已交付 ssr.css + manifest.json
