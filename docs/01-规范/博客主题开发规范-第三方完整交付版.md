## 0. 总览：你要交付什么

### 0.1 交付物清单

一套完整主题 = **6 类文件 + 1 份截图对照 + 1 份自检报告**。

> ⚠️ **整包交付，没有「一期 / 二期」**：列表页、文章页、**五个内页（分类 / 作者 / 标签 / 归档 / 搜索）**、`ssr.css` 必须**同一批交齐**。
> 系统侧的路由与数据（`/app#/blog/cat/:cat` 等内页路由、`ctx.page`、`ctx.tags`、`posts[].file.{author,tags}`）**已全部就绪并可独立验证**，
> 因此「内页等系统好了再补」不是有效理由 —— **缺任何一个内页，验收不通过**。

| # | 交付物 | 位置 | 是否必需 |
|---|---|---|---|
| 1 | `manifest.js` | `web/src/themes/<id>/manifest.js` | ✅ 必需 |
| 2 | `index.js` | `web/src/themes/<id>/index.js` | ✅ 必需 |
| 3 | `<Id>View.vue` 列表页入口 | `web/src/themes/<id>/` | ✅ 必需 |
| 4 | `style.css` | `web/src/themes/<id>/style.css` | ✅ 必需（组件内 `import './style.css'`） |
| 5 | **内页组件 ×5**（分类 / 作者 / 标签 / 归档 / 搜索，按 §4 契约） | 同目录 | ✅ 必需（**一次性交齐，不接受分期**） |
| 6 | `ssr.css` + `manifest.json` | 服务器 `data/themes/<id>/` | ✅ 必需（否则**文章页不跟随主题**） |
| 7 | 设计稿并排对照截图（桌面 + 移动） | 随 PR 提供 | ✅ 验收用 |
| 8 | **自检报告**（`theme-lint.sh` 运行输出） | 随 PR 提供 | ✅ 验收用（v1.1 新增） |
| 9 | **上架预览材料**：封面图 `preview/cover.*` + 样板演示页 `preview/demo.html` + **整页截图 `preview/full-*.png`（≥2 张）** + **主题介绍 `README.md`** | 包内 `preview/` 目录 + 包根 `README.md` | ✅ 必需（v1.3 起，v1.4 补齐截图与介绍，见 §0.4；应用中心上架展示用） |

> **关于第 8 项**：规范里的检查项分两类 —— **机械可判定**的（类名交叉比对、令牌台账、hash 锚点、契约外字段）和**需人工判断**的。前者不要靠人眼，直接跑 `theme-lint.sh`（见附录 E），退出码 `0` 才算过。经验教训：这类缺陷**不会让构建失败、也不会在 console 报警**，但会在真实环境中被用户先发现（详见配套《常见缺陷清单与自检手册》第 0 节）。

### 0.2 主题 id 约定

- kebab-case，仅 `[a-z0-9-]`，长度 ≤ 32（服务端正则 `^[a-z0-9][a-z0-9-]{0,31}$`，非法值会被拒）。
- 交付前请确认 id 不重复：现有内置 id 为 `default / aiklog / minimal / docs / paper / elevated / parchment / emforum / brutal`（与 `settings.go` 白名单、`web/src/themes/all.js` 的 import 列表逐项对应；`default` 为系统兜底，无需 import）。
- ⚠️ **目录存在 ≠ 已接入**：`web/src/themes/<id>/` 目录建好但**没有在 `web/src/themes/all.js` import、也没进 `settings.go` 白名单**时，该主题既不会出现在控制台下拉，也不会进构建产物 —— 属"孤儿目录"。自查方式见附录 E 的自检脚本第 1 节，或直接 `grep` 两处。

### 0.3 三个必须理解的前提

1. **双轨渲染**：公开站有 **SPA 交互版**（`/app#/blog` 列表、`/app#/post/…` 文章）和 **SSR 静态页**（`/blog`、`/{slug}`）两条通道，**同一套主题必须两边都覆盖**（SPA 靠 Vue 组件 + `style.css`，SSR 靠 `ssr.css`）。这是"列表好看、点进去变样"问题的根因，也是本规范 §4 的核心。
2. **文章页也是双轨**：**人看**走 SPA 文章页 `#/post/{token}`（系统提供，随主题走，可带评论/侧栏等插件）；**机器看**走 SSR `/{slug}`（canonical / sitemap / 分享快照）。两者由同一份数据渲染 —— 主题要么声明 `entries.post` 接管 SPA 文章页，要么只投放 `ssr.css` 让 SSR 文章页跟随（此时 SPA 文章页由系统默认页渲染并挂 `.th-<id>`，配色跟随、版式是系统的）。**正文 HTML 由系统注入 `ctx.page.post.html`，主题不负责渲染正文内容本身。**
3. **主题交付有两种形态**（详见 §11）：形态 A = 源码模块，需随前端一起构建（编译进 `web/dist`），**不是运行时可热插的 zip**；形态 B = 声明式主题包（zip），经应用中心 / 本地 zip 安装后，**`ssr.css` 与 `page.html` 均可运行时热投放**（文件落盘即生效，不编译、不重启），作用于公网静态页；形态 A 的 SPA 交互页仍必须重新编译。

### 1.1 `manifest.js`（字段名大小写敏感，逐字段照抄）

```js
export default {
  id: 'aurora',                    // ✅ kebab-case 唯一标识
  title: '极光 Aurora',             // ✅ title（不是 name / nameZh）—— 切换器显示它
  desc: '一句话描述（切换器副标题）',  // ✅ desc（不是 description）
  version: '1.0.0',                // 语义化版本
  pages: ['posts'],                // 主题自带的页面路由键（通用博客主题固定 ['posts']）
  tokens: {                        // 设计令牌说明（键名必须 --th-* 前缀）
    '--th-ink': '正文色',
    '--th-paper': '纸色底',
    '--th-accent': '强调色',
  },
  ui: { themeSwitcher: true },     // 声明「主题页头自带切换器」→ 宿主不再补右上角悬浮版（见 §6）
  dataSources: ['blog'],           // 通用博客主题固定 ['blog']；采集型才用 ['collect']
  dataScope: 'shared',             // ✅ 公开主题固定 'shared'；禁止 'library'
  entries: {                       // 页面级入口声明（见 §4.10）—— 五页必交，缺一即缺项
    post: PostView,
    cat: CatView,              // 也可写 category（两个 key 系统都认）
    author: AuthorView,
    tag: TagView,
    archive: ArchiveView,
    search: SearchView,
  },
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | 见 §0.2 |
| `title` | ✅ | 切换器 / SSR 下拉显示名 |
| `desc` | 建议 | 一句话气质描述 |
| `version` | ✅ | 语义化版本 |
| `dataSources` | ✅ | `['blog']` |
| `dataScope` | ✅ | 固定 `'shared'`（只展示「已分享」内容，系统安全默认） |
| `tokens` | 建议 | 仅作说明用途，实际变量写在 `style.css` 里 |
| `ui.themeSwitcher` | 条件 | 自带切换器时必须声明 `true`（见 §6） |
| `pages` | 可选 | 通用博客主题填 `['posts']` |
| `entries` | ✅ 必填 | 内页组件声明（见 §4.10）：**分类 / 作者 / 标签 / 归档 / 搜索 五个页面全部声明** |

### 1.2 `index.js`（正确写法 —— 模块加载时直接注册）

```js
import { defineAsyncComponent } from 'vue'
import manifest from './manifest.js'
import { registerTheme } from '../index.js'

const theme = {
  ...manifest,
  entry: defineAsyncComponent(() => import('./AuroraView.vue')),
}
registerTheme(theme)
export default theme
```

❌ **错误写法**（永远不会被调用，历史踩坑）：
```js
export default function (app, { registerTheme }) { /* 回调式，永不执行 */ }
```

### 1.3 接入系统（3 处，缺一不可）

1. **注册 import**：在 `web/src/themes/all.js` 追加一行副作用导入（所有主题在此**集中注册**，列表页 `BlogView` 与文章页 `BlogPostView` 共用，不要再在 `BlogView.vue` 顶部散 import —— 否则会出现「列表可选、文章页却掉回默认皮」的割裂）：
   ```js
   import '@/themes/aurora' // 注册极光主题（集中注册表 all.js）
   ```
2. **控制台下拉自动出现**（BlogManage 从注册表 `listThemes()` 动态渲染，无需改代码）。
3. ⚠️ **服务端白名单**（最容易漏）：把新 id 加进 `server/internal/handler/settings.go` 的 `blog.theme` 白名单，否则控制台保存站点主题会被 `SETTING_INVALID` 拒绝：
   ```go
   case "", "default", "aiklog", "minimal", "docs", "paper", "elevated", "parchment", "emforum", "aurora":
   ```

### 1.4 主题生效机制（localStorage 不是权威来源）

```
GET /api/v1/public/site  →  site.theme（settings 表 blog.theme，默认 aiklog）
        ↓
BlogView.applyServerTheme(site.theme) → 激活主题
        ↓
读者本地覆盖 localStorage['aiklog.theme.override'] 优先级更高（切肤用）
```

## 2. 数据契约（`inject`，不是 props）

`BlogView` 渲染主题时 `<component :is="entry" />` **不传任何 props**。数据一律通过 `provide/inject`：

```js
import { inject, computed } from 'vue'
const raw = inject('themeContext')
// 兼容 ref 与普通对象两种包装（不同宿主版本）
const ctx = computed(() => raw?.value || raw || { posts: [], tags: [], loading: true })

const posts    = computed(() => ctx.value.posts    || [])
const tags     = computed(() => ctx.value.tags     || [])
const siteName = computed(() => ctx.value.siteName || '爱库录')
const postUrl  = ctx.value.postUrl   // 单篇地址生成器（函数）
const loading  = computed(() => ctx.value.loading)
const error    = computed(() => ctx.value.error || '')
```

### 2.1 `themeContext` 全字段表

| 字段 | 类型 | 说明 |
|---|---|---|
| `siteName` | string | 站点名（后台「站点设置」） |
| `siteDesc` | string | 站点描述 |
| `posts` | Array | 公开文章列表（见 §2.2） |
| `tags` | Array | 标签云 `[{ name, count }]`（来自 `GET /api/v1/public/tags`，聚合公开文章标签；可能为空数组，见 §4.6） |
| `postUrl(post)` | function → string | **单篇地址生成器，返回 SPA 文章页地址** `#/post/{token}?path=&slug=`（人看主链，随主题走、可带评论等插件，见 §3.1 / §4.3） |
| `postSsrUrl(post)` | function → string | **SSR 静态页地址** `/{slug}`（机器看：canonical / sitemap / 分享快照；分享按钮与 SEO 场景用这个，见 §2.3） |
| `loading` | boolean | 加载中（主题应展示骨架/文案） |
| `error` | string | 错误信息（空串 = 无错） |
| `page` | object | 当前页面参数 `{ kind, cat, author, tag, archive, q }`，由宿主注入（见 §4.10） |

### 2.2 `posts` 条目的真实结构（逐字段核对，禁止臆造）

```js
{
  token: 'xxxxx',        // 公开访问令牌
  path: '分类/文件名.md',  // 相对路径（分类 = 首段目录）
  preview: '纯文本摘要',   // 服务端已生成（AI 摘要或截断，可能为空串）
  file: {
    name: '文件名.md',
    slug: '',            // ⚠️ 早期恒为空串；**当前后端已返回真实 slug**（博客文件均有），可依赖；为兼容旧数据仍建议用 `path` 兜底

    size: 12345,
```

❌ **不存在的字段**（历史上第三方臆造过，全部会渲染出空值）：
`id`（顶层）/ `title` / `summary` / `readTime` / `views` / `contentHtml`。
> 注：`created_at` 字段后端**实际存在**（公开列表 `public/posts` 会返回，博客场景值恒为 0），不要臆造为业务时间；正文更新时间请统一用 `file.updated_at`。`cover`/`excerpt`/`author`/`tags` **已真实下发**（2026-09-17 起），主题可放心使用，但空值兜底不可省。

### 2.3 标题 / 分类 / 日期的派生（与系统 SSR 保持一致）

```js
// 标题：去扩展名（.md 和 .markdown 都要处理）→ 取末段
function title(p) {
  const n = p.file?.name || p.path || ''
  return String(n).replace(/\.(md|markdown)$/i, '').split('/').pop() || '无标题'
}
// 分类：path 首段；无 '/' 则归「未分类」
function cat(p) {
  const path = p.path || ''
  return path.includes('/') ? path.split('/')[0] : ''
}
// 日期：updated_at（毫秒；兼容秒级与字符串）
function date(p) {
  const v = p.file?.updated_at
  if (!v) return ''
  const ms = typeof v === 'number' ? (v > 1e12 ? v : v * 1000) : Date.parse(v)
  if (!Number.isFinite(ms)) return ''
  const d = new Date(ms)
  const z = (n) => String(n).padStart(2, '0')
  return `${d.getFullYear()}-${z(d.getMonth() + 1)}-${z(d.getDate())}`
}
// 链接：必须用 postUrl（返回 SPA 文章页地址），不要自己拼路径
const href = (p) => (ctx.value.postUrl ? ctx.value.postUrl(p) : '#')
// 需要「分享链接 / 面向搜索引擎的静态页」时，用 postSsrUrl（返回 /{slug}）
const shareHref = (p) => (ctx.value.postSsrUrl ? ctx.value.postSsrUrl(p) : '/blog')
```

### 2.4 列表排序（系统已统一，主题不要重排）

系统按「置顶优先 + 更新时间倒序」返回（置顶标记在 `content_state.pinned`）。
**主题不要自行重排 `posts`**，否则与 SSR / RSS 顺序不一致。

### 2.5 内容类型与自定义字段（`file.content_state`）—— 生产站底座 A-G，v1.4 新增

`file.content_state` 是一个 **JSON 字符串**（可能为空串），同一对象内同时承载两类字段，互不干扰：

| 字段 | 归属 | 说明 |
|---|---|---|
| `visibility` / `status` | AiKlog 原有 | 可见性 / 发布态（系统已消费，主题一般无需处理） |
| `node_type` | 底座 A-G | 内容类型：`article`（默认）/ `resource`（资源）/ `link`（外链）/ `doc` / `tool` |
| `fields` | 底座 A-G | 自定义业务字段对象（如 `download_url` / `version` / `platform` / `url` / `price` …） |
| `pinned` | 系统 | 置顶标记（系统已排序，主题勿重排） |

**读取方式：请复用系统共享工具，不要各主题各写一份解析**：

```js
import { nodeTypeOf, nodeTypeLabel, parseContentState, fieldList } from '@/utils/contentState'

nodeTypeOf(p.file)                 // → 'resource' | ''（安全解析，任何异常回退空串）
nodeTypeLabel(nodeTypeOf(p.file))  // → '资源' | '外链' | '文章' …
parseContentState(p.file)          // → { visibility, status, nodeType, fields }
fieldList(p.file)                  // → [{ key, label, value }]（fields 的中文标签化列表）
```

**列表卡渲染建议**：在 meta 行加一个类型角标，资源 / 外链文章一眼可辨：

```html
<span v-if="nodeTypeOf(p.file)" class="card-type">{{ nodeTypeLabel(nodeTypeOf(p.file)) }}</span>
```

- **参考实现**：内置默认主题 `aiklog` 已接入（`web/src/themes/aiklog/AiklogView.vue` + `style.css` 的 `.ak-card-type`），其余主题可直接照抄。
- **文章详情页的按类型差异化区块**（资源下载区 / 外链卡 / `fields` 信息卡）由**系统**在公开文章页统一提供（组件 `ContentStatePanel`），主题无需重复实现；形态 B（声明式主题包）的 `page.html` 可在 SSR 侧读取 `file.content_state` 做同类渲染。

### 3.1 渲染双通道 + 页面清单

| # | 页面 | SPA 路由（交互版） | SSR 路由（SEO 主页） | 主题职责 | 系统实现状态 |
|---|---|---|---|---|---|
| 1 | **列表页** | `/app#/blog` | `/blog` | Vue 组件（`entry`）+ `style.css`；SSR 靠 `ssr.css` | ✅ 已上线 |

| 3 | **分类页** | `/app#/blog/cat/:cat` | 待补 | `entries.cat`（或 `category`）组件 | ✅ 已上线（§4.4） |
| 4 | **作者页** | `/app#/blog/author/:author` | 待补 | `entries.author` 组件 | ✅ 已上线（§4.5） |

> **交付范围 = 页面 1~7 全部**（页面 8 由系统兜底，主题不处理）。
> **没有一期 / 二期**：五个内页（3~7）与列表页、文章页**同一批交付**。系统侧内页路由（`/app#/blog/cat/:cat`、`/app#/blog/author/:author`、`/app#/blog/tag/:tag`、`/app#/blog/archive/:ym`、`/app#/blog/search`）、`ctx.page`、`ctx.tags`、`posts[].file.{author,tags}` **均已就绪**，
> 五个内页的 `entries` key 为 `cat`（别名 `category`）/ `author` / `tag` / `archive` / `search`（§4.10）。**缺任一内页 = 交付缺项，验收不通过。**

### 3.2 页面级设计的统一要求

- 所有页面**共用同一套设计令牌**（`--th-*`）、同一页头/页脚组件结构 —— 保证换页不割裂。
- 页面组件同样用 `inject('themeContext')` 取数；内页额外从 `ctx.page` 读当前页参数（§4.10）。
- 未提供某内页组件的主题，系统用**默认页 + 你的 `tokens`** 渲染 —— 即"配色字体一致、版式是系统的"。这是**兜底机制，不是允许少交内页的许可**：按 §0.1，**内页组件与 `ssr.css` 同为必修项**，未交内页属交付缺项。
- ⚠️ **宿主公开页是 hash 路由**（形如 `#/blog?view=public`）—— **`#` 后面是路由状态，不是滚动锚点**。由此产生三条硬约束（v1.1 新增，详见 §9.3 与附录 C.2）：
  - **禁止**把页内锚点写进 `href`（`href="#y-2026"`）或 `location.hash` —— 等于向 router 塞一段非法路由，可能跳转/白屏，刷新后地址栏还会残留异常 hash；
  - 页内跳转（年份/月份锚点、目录跳转、回到顶部等）一律用 `<button>` + `el.scrollIntoView({ behavior: 'smooth' })`；
  - 站内页面跳转一律用 `ctx.postUrl(post)`（SPA 文章页）或相对路径，**不要手拼 `#/p/`、`#/post/`**；分享按钮/SEO 场景用 `ctx.postSsrUrl(post)`（`/{slug}`）。
  - 注意这类问题**在 iframe 预览与 `file://` 打开时都不复现**，只在真实地址栏环境下暴露 —— 别指望开发期自己发现。

## 4. 各页面详细规范

### 4.1 列表页（`entry`）—— 必做

- 渲染整页（含页头、导航、文章列表、页脚）。
- 数据：`ctx.posts`；状态：`loading` / `error` / 空态（三者都要处理）。
- 空态文案示例：`还没有公开文章`。

### 4.2 列表页 SSR（`/blog`）—— 必做

SSR 列表页默认由系统模板渲染（`blogHTMLTmpl`），主题可用两种方式定制（二者可叠加）：

1. **只换肤**：投放 `ssr.css` 覆盖类名与变量（见 §5.4 + 附录 A）。**不要改 Go 源码。**
2. **换版式**：随包投放 `page.html` —— 系统在请求时优先使用它渲染列表页与文章页（v1.1 新增，免编译，见 **§11**）。
   `page.html` 缺失或解析失败时自动回退内置模板，不影响公开页可用性。

### 4.3 文章页（双轨：SPA `#/post/{token}` + SSR `/{slug}`）—— 必做

**同一篇文章有两条人可到达的路径**，职责不同，**两条都要在**：

| | SPA 文章页（人看主链） | SSR 静态页（机器看） |
|---|---|---|
| 地址 | `/app#/post/{token}?path=…&slug=…` | `/{slug}`（`/blog/{slug}` 兼容） |
| 渲染方 | 主题 `entries.post`（声明则接管）／系统默认 `BlogPostView` | 系统模板 + 你的 `ssr.css` |
| 你负责 | 声明 `entries.post` 组件（可选，强烈建议） | 投放 `ssr.css`（**必修**） |
| 用途 | 阅读体验、评论、侧栏、换肤 | canonical / sitemap / 分享快照 |

**A. SSR 侧（必修，交付项）**

- **正文由系统用 goldmark 渲染进 `.body`**，主题不参与正文渲染。
- 主题职责 = 投放 `ssr.css`，覆盖：
  - 变量：`--ink / --ink2 / --ink3 / --paper / --line / --jade / --card / --font-d`
  - 类名：`.wrap`、`header.site`、`nav.top`、`article h1`、`.meta`、`.body *`、`footer`
- ⚠️ **列表页与文章页共用同一份 `ssr.css`** → 一次投放，两页同时跟随主题。
- ⚠️ 只覆盖**模板中已存在的类名**，不要臆造钩子（附录 A 是完整清单）。

**A2. 评论区与锚点落点（v1.4.4 新增 · 必修接线）**

- 文章页 SSR **会渲染「已通过」评论**（`status='approved'`，按时间正序，上限 200 条），
  整体挂在 `<section class="cmts" id="comments">` 下，**每条评论带 `id="comment-{评论id}"`**。
- 为什么必须有：评论收录（内容引用与归因）会给出一段**归因区块**，其中的回指链接形如
  `{origin}/{slug}#comment-{id}` —— **这个 id 就是它的落点**。SSR 页此前不渲染评论，
  点回指链接会停在页首（SPA 侧有落点、SSR 侧没有）。
- 模板数据新增字段 **`{{.Comments}}`**（数组，元素 `{ID, Author, Date, Body}`）：
  - `Body` 是**纯文本且已 HTML 转义**。评论是访客可写内容，SSR 侧**不再解析 Markdown** ——
    多一层解析就多一层 XSS 面；换行由 CSS `white-space: pre-wrap` 保留。
  - `Author` 解析顺序：访客昵称 → 用户 `display_name` → 角色兜底（管理员 / 读者）。
  - 条数用 `{{len .Comments}}` 取，**没有单独的计数字段**。
- **自带 `page.html` 时必须自己 `{{range .Comments}}` 渲染**，否则你的 SSR 页没有评论区、锚点仍无落点。
  可直接照抄内置模板那一段（类名见附录 A）。
- `.cmt:target` 是锚点落点高亮（跳过来时描边），建议保留。
- 正文里的 **`@提及`** 由宿主渲染为 `<span class="mention">`（显式写法额外带 `data-mention-id`）。
  SSR 侧选择器写作 `.body .mention`；宿主已给全局默认样式，主题可自行覆盖配色。

**A3. 公开媒体元信息（v1.4.5 新增 · 可选消费）**

宿主提供**匿名可读**的媒体元信息端点，用于在公开页展示图片尺寸 / 视频时长与分辨率 / 音频时长：

```
GET /api/v1/public/media/{file_id}/info        # 匿名，无需登录
→ 200 { file_id, kind, width, height, duration_ms, codec, bitrate, probe_status }
```

- `kind` ∈ `image` | `video` | `audio` —— **判类型一律用 `kind`，不要用宽高**
  （纯音频的 `width`/`height` 恒为 0，音频会被误渲染成 0x0 黑框）。
- `duration_ms` 为 **0 表示未知**（如非本地存储后端或未装 ffprobe），**不要**当成"0 秒"渲染。
- `probe_status` ∈ `ok` | `unsupported` | `failed`。⚠️ **主题必须容忍 `unsupported`**：
  渲染成"时长未知"即可，**不要因此隐藏播放器/图片**。
- **边界**：仅**博客目录子树内**的 `image/*` `video/*` `audio/*`（`image/svg+xml` 明确排除 ——
  活性文档不公开直出）；越界或不存在的文件一律 **404**（不区分原因），非法 id 返 **400**。
- 公开媒体**字节**端点（`GET /api/v1/public/media/{id}`）同样是该子树 + 三类 mime，
  且**支持 `Range`** —— 视频可直接 `<video controls :src>` 播放、可拖动进度，无需另建通道。

**B. SPA 侧（可选但强烈建议）**

- 系统默认文章页（`BlogPostView`）已可用：标题、正文、meta、返回列表、插件槽（评论 / 相关推荐 / AI 阅读 / 统计）、分享链接俱全，并**自动挂 `.th-<id>` class**。
- 主题声明 `entries.post` 后，整页换由你的组件渲染，从 `ctx.page.post` 取数：

  `{ token, path, slug, title, html, cat, category, author, updatedAt, size }`

  - `html` 是**已渲染好的正文 HTML**（系统已完成 Markdown 渲染），用 `v-html` 输出即可；
  - `ctx.posts` 仍是完整列表，可用于「相关文章 / 上下篇」；
  - 「相关文章」链接用 `ctx.postUrl(post)`，「分享链接」用 `ctx.postSsrUrl(post)`。
- 不声明时：系统默认版式 + 你的 `.th-<id>` 钩子 —— 主题可在 `style.css` 里写
  `.th-<你的id> { --th-ink: …; --th-paper: … }` 让默认文章页也跟随配色/字体。
- ⚠️ **"列表是主题风、点进文章掉回系统默认皮"是最高频的体验割裂**。要根治必须声明 `entries.post`。

> ⚠️ 不要指望用 SPA 文章页承接 SEO：hash 路由不会被搜索引擎当作独立页面收录，canonical 与 sitemap 仍指向 SSR `/{slug}`。**人看 SPA、机器看 SSR**，两者互补，缺一即割裂。

### 4.4 分类页（`entries.cat`，别名 `entries.category`）—— 必做

- **语义**：分类 = 博客目录的**首段子目录**（`分类/文件名.md` → 分类 `分类`）。
- **SPA 路由**：`/app#/blog/cat/:cat`（对齐上游 `/blog/cat/{cat}`）。
- **数据**：`ctx.page.cat`（当前分类名）+ `ctx.posts`（按 `path` 首段 === `cat` 过滤）。
- **组件契约（系统路由已上线，可直接端到端验证）**：


### 4.5 作者页（`entries.author`）—— 必做

- **语义**：公开文章按作者过滤（系统作者白名单 + 每篇 `author_id`）。
- **SPA 路由**：`/app#/blog/author/:author`（对齐上游 `/blog/author/{username}`）。
- **数据**：`ctx.page.author` + `ctx.posts`（按 `post.file.author` 过滤，系统已下发该字段；空值按站点 owner 回落）。
- 组件结构与分类页同构，仅过滤条件与标题不同（`作者：{{ author }}`）。

### 4.6 标签页（`entries.tag`）—— 必做

- **SPA 路由**：`/app#/blog/tag/:tag`（等价 query 形态 `#/blog?tag=xxx`）。
- **数据**：`ctx.tags`（`{ name, count }[]`，系统按公开文章聚合，**不再是空数组**）+ `ctx.page.tag`（当前标签）。
- **每篇文章的标签**：`post.file.tags`（`string[]`，无标签时为空数组）—— 标签内页据此过滤。

规则：

1. 标签云区块用 `v-if="tags && tags.length"` 包裹（站点确实没有标签时自动隐藏，不占位）；
2. 遍历对象是 `{ name, count }`，必须写 `{{ t.name }}`（写 `{{ t }}` 会渲染 `[object Object]`）；
3. 标签项渲染为**可点链接**：`<a :href="'#/blog/tag/' + encodeURIComponent(t.name)">` —— 系统路由已支持，**不再是死链**；
4. 标签内页按 `(post.file?.tags || []).includes(ctx.page.tag)` 过滤 `ctx.posts`，空态文案「该标签下暂无文章」；
5. 未接管 `entries.tag` 时系统仍会用默认内页兜底渲染（套你的 `--th-*` 令牌）—— 但按 §0.1 这属于**交付缺项**。

### 4.7 归档页（`entries.archive`）—— 必做（前端派生）

- **数据**：从 `ctx.posts` 按 `updated_at` 分组年月自行派生（系统不提供归档接口）。
- **路由**：`#/blog/archive/YYYY-MM` 或 `#/blog?archive=YYYY-MM`（两者等价，参数取 `ctx.page.archive`）。
- 组件需自行实现「年月分组折叠/列表」排版。

### 4.8 搜索页（`entries.search`）—— 必做（前端派生）

- **数据**：`ctx.page.q`（来自 `#/blog/search?q=xxx`）+ 在 `ctx.posts` 内做客户端匹配（标题/摘要）。
- ⚠️ 客户端搜索**只覆盖已加载的公开文章**；后续系统若提供公开搜索接口再切换。
- 必须处理空关键词、无结果、加载中三态。

### 4.9 404 —— 系统兜底，主题无需处理

系统层补全前，未知 slug 由 SSR 兜底（站点默认主题样式 + 提示）。主题不要自行实现 404 页。

### 4.10 `entries` 声明契约 + `ctx.page`

主题在 `manifest.js` 声明要接管的页面组件：

```js
import CatView from './CatView.vue'
import AuthorView from './AuthorView.vue'
// ...
export default {
  // ...其他字段
  entries: {
    post: PostView, cat: CatView, author: AuthorView,
    tag: TagView, archive: ArchiveView, search: SearchView,
  },
}
```

系统按 `pageEntry(theme, page)` 取入口：
`list` → `theme.entry`；`post/cat/author/tag/archive/search` → `theme.entries[page]`，**未声明则回退系统默认页**（但套用你的 `--th-*` 令牌，保证整站气质一致）。

内页组件从 `ctx.page` 读当前页参数：

```js
{ kind: 'post'|'cat'|'author'|'tag'|'archive'|'search',  // 当前页面类型
  cat?: string, author?: string, tag?: string,
  archive?: string, q?: string, post?: object }
```

> ✅ **系统侧已全部就绪**：列表页与内页由 `BlogView` 统一 provide `themeContext`（含 `posts` / `tags` / `page`），并按 `pageEntry(theme, page.kind)` 分发到 `theme.entry`（`list`）或 `theme.entries.*`（内页）；文章页 `BlogPostView` 同样 provide `ctx.page` 并按 `entries.post` 分发。
> `entries` 的 `cat` / `category` 两个 key 系统都认（互为别名），主题写其一即可。
> 内页路由（`/app#/blog/cat/:cat`、`/blog/author/:author`、`/blog/tag/:tag`、`/blog/archive/:ym`、`/blog/search`）与 `ctx.tags`（`GET /api/v1/public/tags`）**均已上线**；未声明某内页时系统用默认内页兜底并套用你的 `--th-*` 令牌（但那是兜底，不是少交的理由）。

## 5. 样式规范

### 5.1 三条硬规则

1. **`style.css` 必须在入口组件里显式引入**：`import './style.css'`（漏掉 = 整页无样式）。
2. **Reset 必须完整**（后代通配符不能漏 —— 历史踩坑）：
   ```css
   .au-root, .au-root *, .au-root *::before, .au-root *::after {
     margin: 0; padding: 0; box-sizing: border-box;
   }
   ```
3. **作用域隔离**：所有选择器挂在**主题根类**下（`.au-root …`），CSS 变量统一 `--th-*` 前缀 —— 禁止污染主应用与其它主题。

### 5.2 设计令牌（`--th-*`）

在主题根类上定义，供自身与系统默认页共用：

```css
.au-root {
  --th-ink: #1c1917;      /* 正文 */
  --th-ink-2: #57534e;    /* 次要文字 */
  --th-ink-3: #a8a29e;    /* 弱化文字 */
  --th-paper: #fafaf9;    /* 页面底 */
  --th-card: #ffffff;     /* 卡片底 */
  --th-line: #e7e5e4;     /* 分隔线 */
  --th-accent: #0f766e;   /* 强调色 */
  --th-font-d: Georgia, 'Songti SC', 'SimSun', serif;          /* 标题字体 */
  --th-font-b: system-ui, -apple-system, 'PingFang SC', sans-serif; /* 正文字体 */
}
```

### 5.3 其它约束

- **语义化标签**：站名用 `<div>`/`<p>`，**不要用 `<h1>`**（`h1` 是文章页的，SSR 才该有）。
- **删除死 CSS**：组件里无对应模板的规则必须删掉（历史教训：某主题带了 ~350 行文章页/评论/分页死代码，误导后续维护，15KB → 8KB）。
- **配色贴设计稿要逐值核对**：渐变、噪点层、暗/亮底适配；亮色主题的占位渐变必须用**低饱和同底色系**，禁止把暗色渐变直接搬到亮底上。
- **移动端断点**必须做（验收项）。

### 5.4 SSR 侧样式（`ssr.css`）

投放位置：`服务器 data/themes/<id>/ssr.css`（按可执行文件上级目录解析：`bin/../data/themes`，与存储根一致，不依赖 cwd）。

配套 `data/themes/<id>/manifest.json`：

```json
{ "title": "极光 Aurora", "version": "1.0.0" }
```

`ssr.css` 内容形状（**只覆盖附录 A 的类名与变量**）：

```css
/* 外置主题：aurora —— 覆盖 SSR 列表页与文章页 */
:root {
  --ink: #1c1917; --ink2: #57534e; --ink3: #a8a29e;
  --paper: #fafaf9; --line: #e7e5e4; --jade: #0f766e; --card: #fff;
  --font-d: Georgia, 'Songti SC', serif;
}
.wrap, header.site .in, footer { max-width: 640px; }
header.site { background: transparent; border-bottom-color: var(--line); }
.list li { border: none; border-bottom: 1px solid var(--line); border-radius: 0; padding: 22px 0; }
.list a { font-size: 22px; }
article h1 { font-size: 26px; }
.body pre { background: #1a2332; color: #d7e0ea; border-radius: 8px; }
```

系统加载机制（无需你操作）：
- `blogThemeOptions()` 自动把 `data/themes/` 下目录加进 SSR 页头下拉；
- `blogThemeIDFor()` 支持 `?theme=<id>` 预览；
- `blogThemeCSS()` 优先读外置 `ssr.css`（**256KB 上限**，按 mtime 缓存，热更新即生效）。

## 6. 主题切换器（`ThemeSwitch`）

组件：`@/components/ThemeSwitch.vue`，两种模式：

| 模式 | 用法 | 要求 |
|---|---|---|
| `inline`（默认） | 主题在自己的页头 nav 里渲染（紧邻 RSS） | manifest 必须声明 `ui: { themeSwitcher: true }` |
| `dock` | 宿主（BlogView）在右上角渲染的悬浮兜底版 | 无需主题操作 |

```vue
<nav class="au-nav">
  <ThemeSwitch />   <!-- inline：主题自带切换器 -->
  <a :href="rssHref">RSS</a>
</nav>
```

规则：
- **自带切换器** → 声明 `ui.themeSwitcher: true`。**不声明 / 不渲染** → 宿主自动补 dock 版，保证任何主题都能换肤。
- 切换结果写 `localStorage['aiklog.theme.override']`（优先级高于站点设置）；站长可「设为站点主题」变成全站默认。
- **SSR 页**（`/blog`、`/{slug}`）页头有原生 `<select name="theme">` 下拉，提交即 `?theme=` 预览（选项来自 `blogThemeOptions()`）。

## 7. 服务端接口约定（可选能力）

### 7.1 AI 问答（若主题实现）

- 端点：`POST /api/v1/public/blog/ask`
- 请求：`{ "question": "..." }`
- 响应：**`{ "reply": "..." }`** —— 读 `reply`，❌ 不是 `answer`
- **必须处理 HTTP 429 限流**（每 5 分钟 8 次），给用户友好提示
- 输入为空时禁用按钮；请求中显示 loading

### 7.2 其它公开接口

| 用途 | 端点 |
|---|---|
| 公开文章列表 | `GET /api/v1/public/posts` |
| 站点信息（含当前主题） | `GET /api/v1/public/site` |
| RSS | `GET /api/v1/blog/feed.xml` |
| Sitemap | `GET /api/v1/blog/sitemap.xml` |
| 阅读计数 | `POST /api/v1/public/blog/pv` / `GET /api/v1/public/blog/pv` |

### 7.3 归档/统计

从 `posts` 自行派生（按 `updated_at` 分组年月、计数），**不要指望接口提供**。

### 7.4 平台新能力与主题边界（v1.3 增补 · 2026-09-17 底座上线后）

平台已上线一批底座能力，主题开发方按下列边界处理，**不得臆造字段、不得绕过宿主**：

| 能力 | 主题侧约定 |
|---|---|
| **密码保护文章** | 宿主在公开正文接口上强制 401 `PASSWORD_REQUIRED` 闸门 + HMAC 解锁凭证（24h）。SPA 公开页的解锁交互由**宿主组件**承担；主题在拿不到正文的场景（如 SSR 预渲染、正文接口 401）按"内容受保护"空态展示，**禁止**自行实现密码输入框或绕过闸门 |
| **定时发布文章** | 未到 `publish_at` 的文章宿主已在公开轨过滤，`posts` 里**不会出现**；主题无需也无法感知 |
| **置顶** | 列表顺序由宿主统一排序（全局置顶 → 分类置顶 → pin_order → 时间），主题**只渲染 `posts` 顺序，不要重排**（与 §2.4 同源） |
| **评论** | 宿主内置 `blog-comments` 组件（挂 `post_bottom`），访客评论默认待审、过审后展示。主题如需自定义评论区，消费同一公开接口 `GET /api/v1/public/comments`，**不要**另建写入通道 |
| **阅读计数** | 数据口径归宿主（`files.view_count`，去重防刷后聚合）。`themeContext.posts` 当前**不含** view_count 字段——主题想展示阅读量就走 `GET /api/v1/public/blog/pv`，**不要**臆造 `posts[].views` |
| **custom_css / custom_js** | 站长级注入（`/app#/manage/blog` 站点设置），宿主在公开页幂等注入。主题的 `ssr.css` / `style.css` 优先级低于站长 custom_css 是**预期行为**，不得用 `!important` 全局对抗 |
| **RSS i18n 同源** | RSS `language` 取 `blog.locale`、`link` 取 `blog.base_url`（站点设置）。主题无感，但 SSR 页若自行输出 `hreflang`/`canonical`，基准 URL 必须与 `blog.base_url` 一致 |
| **分类层级（多级目录）** | 博客目录的**子目录**即子分类：文章 `path` 形如 `tech/ai/xxx`，前缀即分类层级。分类链接允许携带多级段 `#/blog/cat/tech/ai`；**分类页数据由宿主过滤后 provide，主题不得自行按 path 过滤或分组**。展示层级时用 `/` 原样呈现（如 `tech / ai`）；在宿主透出结构化分类树数据源之前，主题**不要**自行从 path 推断构建多级导航树 |
| **主题自设置（options_schema）** | 主题可在 manifest 声明 `options_schema[]`（key/label/type/default/group），type 词汇表与插件 `settings_schema` **同一套**：`text / textarea / number / boolean / color / select / multi-select / ordered-list`。宿主按声明自动渲染站长设置表单并存储下发，**主题不自带设置页 UI**。运行时消费 `/public/site` 的 `theme_settings`（未配置时用 schema default 兜底）；优先级链 = **主题默认值 < 站长主题设置 < 站长 custom_css（最高）**。板块/侧栏排序用 `ordered-list` 项由主题自行渲染，宿主不做统一侧栏注册表。未声明 schema 的主题按"无设置项"处理，无需改动即兼容 |
| **日夜模式** | **站长级默认**（白天/夜间/跟随系统）走 options_schema 声明一个 `select` 项；**读者级偏好**由主题自管 localStorage（键名 `th-<id>-mode`，仅限轻偏好，不得存其它数据到宿主命名空间）。SSR 机器轨是静态页，**只跟随站长级默认**（宿主经 `{{.ThemeVars}}` 注入 CSS 变量），不实现读者手动切换。主题默认 `dark` 配色时必须同时保证默认（浅色）形态可读 |
| **AI 对话窗** | 公开端点 **`POST /api/v1/public/blog/ask`**（`{question, path?}` → `{reply, degraded}`）已内置，主题可直接布置 AI 对话窗。边界：**单轮问答**，不带/不伪造会话历史；`question` ≤ 800 字；请求进行中禁止重复提交（宿主有 IP 限流）；`degraded=true` 时降级展示（提示 AI 暂不可用）；站长可用 `blog.ai_ask_open` 单独关闭该能力，主题须把关闭态处理为隐藏入口而非报错。**禁止**另建 AI 写入通道或代理转发到第三方 AI 接口 |

**单包交付铁律（重申）**：一个主题 = 一个 manifest = 一个完整包 = 一个版本号。宿主侧每个主题版本都要**重新编译嵌入 + 应用中心上架**，因此**任何增量功能（哪怕只改一个组件）都必须 bump version 后整包重发**，不存在"补丁包 / 增量包 / 二期追加"的形态——分批交付会导致宿主编译产物与包版本错位，上架即乱。

### 9.3 交付前机械自检（v1.1 新增 · 提交前必须全过）

> **为什么单列一节**：以下 6 项的共同特征是 —— **构建不会失败、console 不会报警、代码看起来完全正常**，只有真正点进去用、或逐行读命名与文案时才会发现。人眼在这类检查上天然不可靠，因此**尽量交给工具**：跑 `theme-lint.sh`（附录 E），退出码 `0` 才算过**前 5 项**；第 6 项（grid/flex 子项 `min-width:0`）需结合布局语义，**当前由人工核对**（脚本暂未自动化）。

```bash
cd web/src/themes/<id>
bash theme-lint.sh          # 类名前缀自动推断；也可显式传参，如 bash theme-lint.sh bt-
echo $?                     # 0 = 通过；1 = 存在必修项
```

| # | 检查项 | 判定 | 依据 |
|---|---|---|---|
| 1 | **无悬空类**（模板有类名、CSS 无规则）与**无死 CSS** | 脚本第 1 节两条输出均为空（动态拼接类需人工排除） | §5.1 |
| 2 | **`manifest.tokens` 台账一致** | 脚本第 2 节无漏报、无虚报 | §1.1 · §5.2 |
| 3 | **无 hash 路由锚点** | 脚本第 3 节为空：既无 `href="#x"`，也无 `:href="'#' + x"`、`location.hash =` | §3.1 · §8.3 |
| 4 | **无不可验证文案** | 脚本第 4 节 `[!]` 项逐条确认：每个形容词都能被真实字段证明 | §2.2 |
| 5 | **无契约外字段** | 脚本第 5 节为空：不出现 `.views/.likes/.comments/.cover/.summary/.readTime/.comnum` | §2.2 |
| 6 | **grid/flex 子项已加 `min-width: 0`** | 人工核对（长标题、输入框撑破列宽的高频疏漏） | §5.3 |

**两条容易被忽略、但与构建无关的硬要求**：

- **页内跳转一律 `button` + `scrollIntoView()`** —— 宿主公开页是 **hash 路由**（`#/blog?view=public`），`#` 后面是**路由状态而非滚动锚点**。把 `#y-2026` 写进 `href` 等于向 router 塞一段非法路由，可能跳走或白屏，且**刷新后地址栏残留**。此问题在 iframe 预览与 `file://` 下均不复现，只在真实地址栏环境暴露。
- **文案只描述可证事实** —— 拿不准时用中性词（最新/近期/全部/本篇），而非品质词（热门/精选/推荐/排行）。一句话原则：**描述位置安全（头条 ✓），描述品质危险（精选 ✗）**。

## 11. 交付形态 B：声明式主题包（免编译，装 zip 即用）

> v1.1 新增。形态 A（源码模块）见 §0–§10；本节是**第三方分发/市场包**的形态。

### 11.1 两种形态怎么选

| 维度 | 形态 A：完整主题（源码模块） | 形态 B：声明式主题包（zip） |
|---|---|---|
| 作用面 | 交互版 SPA（`#/blog`）+ 公网静态页 | **公网静态页** `/blog`、`/blog/{slug}`、`/{slug}` |
| 能做什么 | Vue 组件：内页、侧栏、搜索、AI 问答… | **换版式**（`page.html`）+ **换肤**（`ssr.css`） |
| 安装方式 | 源码入库 + 随主系统构建 | 应用中心一键安装 / 本地 zip 安装 |
| 需要重新编译主系统？ | **需要**（只有运维方有构建环境） | **不需要**（管理员装完即生效） |
| 适合 | 官方主题、深度定制、要交互页 | 第三方分发、市场包、快速上线 |

⚠️ **"重新编译"这件事决定了谁能装主题**：形态 A 必须由具备 Node+Vite+Go 构建环境的一方执行；形态 B 任何管理员都能装。两者可组合：同一主题先以 B 上线公网站点，再由运维加入 A 获得交互版。

### 11.2 为什么形态 B 能免编译（机制，务必理解）

系统是**双轨渲染**：

- **SPA 轨**：主题 = Vue 单文件组件 → 静态 import → Vite 编译进 `dist` → `go:embed` 进二进制 → **必须重新编译**。
- **SSR 轨（公网/SEO 轨）**：系统在**每次请求时**读取 `data/themes/<id>/ssr.css` 与 `page.html`（按 mtime 缓存）→ **文件落盘即生效**，不编译、不重启。

形态 B 只作用于 SSR 轨，所以"装 zip 即用"成立。

### 11.3 包结构（白名单，路径大小写敏感）

| 包内路径（任选其一同义） | 落地为 | 用途 | 上限 |
|---|---|---|---|
| `manifest.json` / `theme/manifest.json` | `data/themes/<id>/manifest.json` | 元信息 | 512 KB |
| `ssr.css` / `theme.css` / `theme/ssr.css` / `theme/theme.css` | `data/themes/<id>/ssr.css` | 换肤 | 256 KB |
| `page.html` / `theme/page.html` | `data/themes/<id>/page.html` | 换版式 | 512 KB |

- 白名单之外的文件**一律忽略**（不会被落盘），可安全携带 README、设计稿等。
- 必须含 `manifest.json`，且**至少含 `ssr.css` 或 `page.html` 之一**，否则安装被拒（`APP_THEME_EMPTY` / `MARKET_THEME_EMPTY`）。

### 11.4 `manifest.json`

```json
{
  "id": "yourtheme",
  "name": "你的主题名",
  "version": "1.0.0",
  "kind": "theme",
  "description": "一句话说明",
  "author": "你的署名"
}
```

- **`kind` 必须为 `"theme"`**（否则按插件处理，不做主题投放）。
- `id` 规则：小写字母/数字/`.`/`-`，≤64 字符，不含 `..`。`id` 同时是目录名，**确定后不要改**。
- 与形态 A 一致：`id` 是主题身份，切换/卸载都按它索引。

### 11.5 `ssr.css`

与 §5.4 同一套约束：只覆盖**附录 A 已存在的类名与 8 个 CSS 变量**，写自己的前缀规则即可，不要臆造钩子、不要写依赖 JS 的效果。一份样式同时作用于列表页与文章页。

### 11.6 `page.html`（换版式）

用 Go `html/template` 语法（模板引擎通用，写法接近 Jinja/Handlebars）：

- 取值：`{{.Title}}`、`{{.SiteName}}` …
- 循环：`{{range .Items}} … {{end}}`
- 分支：`{{if .IsList}} … {{else}} … {{end}}`

**可用字段（顶层，全部可直接取用）**

| 字段 | 含义 |
|---|---|
| `SiteName` / `SiteTag` | 站点名 / 副标题 |
| `Title` / `Description` | 页面标题 / 描述 |
| `Canonical` / `RSS` | 规范链接 / RSS 地址 |
| `IsList` | 是否列表页（`true` = 列表，`false` = 文章） |
| `Items` | 列表条目（见下） |
| `BodyHTML` | 文章正文 HTML（已由系统渲染，**不要再转义**） |
| `Date` / `Cat` | 日期 / 分类 |
| `JSONLD` | 结构化数据（放入 `<script type="application/ld+json">`） |
| `ThemeID` | 当前主题 id |
| `ThemeCSS` | 本主题 `ssr.css` 内容（放入 `<style>`） |
| `Themes` | 主题下拉项（`{ID, Title}`） |

**`Items` 条目字段**：`Slug`（文章相对路径，拼接为 `href="/{{.Slug}}"`）、`Title`、`Preview`、`Date`、`Cat`。

**三条硬要求**

1. **必须包含 `{{.ThemeCSS}}`**（放进 `<style>`），否则你的 `ssr.css` 不会生效。
2. 文章页正文用 `{{.BodyHTML}}` —— 系统已按安全类型处理，写成 `{{html .BodyHTML}}` 或手工转义都会导致正文显示异常。
3. html/template 会**移除 HTML 注释**，不要用注释当自检标记（请用独有 class 名）。

**主题下拉（可选，需要让读者切主题时加）**

```html
{{if .Themes}}<form method="get" action="">
  <select name="theme" onchange="this.form.submit()">
  {{range .Themes}}<option value="{{.ID}}"{{if eq .ID $.ThemeID}} selected{{end}}>{{.Title}}</option>{{end}}
  </select>
</form>{{end}}
```

**兜底保证**：`page.html` 缺失、超限或语法错误时，系统会记一条日志并**自动回退内置模板**，公开页不会 500。

### 11.7 安装 · 生效 · 卸载

| 动作 | 方式 |
|---|---|
| 安装 | 应用中心「主题」→ 安装；或后台本地 zip 安装（`POST /api/v1/admin/apps/install-zip`，表单字段 `file`） |
| 即时预览（不影响线上） | `/blog?theme=<id>`、`/blog/{slug}?theme=<id>` |
| 设为站点主题 | 博客管理 → 主题下拉（**已安装的外置主题会自动出现，不需要改前端或后端白名单**） |

| 生效范围 | 公网静态页（列表 + 文章）。交互版 `#/blog` 未注册该主题时回退默认 |

### 11.8 形态 B 自检清单

1. zip 内只有白名单文件；`manifest.json.kind == "theme"`；`id` 合规
2. 至少含 `ssr.css` 或 `page.html`
3. `page.html` 含 `{{.ThemeCSS}}`
4. `?theme=<id>` 预览：**列表页与文章页都正确**（含正文、日期、分类、链接可点）
5. 空数据/无正文不报错（`{{if not .Items}}` 兜底）
6. 卸载后 `/blog` 完全恢复（无残留样式、目录已清理）
7. 移动端（≤720px/960px）自测

## 附录 C：常见错误与反面教材

### C.1 协议与结构类

| 错误 | 后果 | 正确做法 |
|---|---|---|
| `index.js` 用回调式导出 | 主题永不注册 | 模块加载时直接 `registerTheme` |
| manifest 用 `name`/`description` | 切换器显示空 | 用 `title`/`desc` |
| 忘记 `import './style.css'` | 整页无样式 | 入口组件内显式引入 |
| reset 漏 `.xx-root *` | 后代 UA margin 未清 | 通配符四件套（§5.1.2） |
| 站名用 `<h1>` | SEO 语义冲突 | 用 `<div>`/`<p>` |
| 标签云 `{{ t }}` | 渲染 `[object Object]` | 写 `{{ t.name }}` |
| 标签云/分类云输出自造链接 | 404 死链 | 用系统内页路由：标签 `#/blog/tag/<name>`、分类 `#/blog/cat/<name>` |
| 让列表文章全部跳 SSR 静态页 | 人看侧脱离主题、无评论/侧栏 | 列表用 `ctx.postUrl`（SPA）；分享/SEO 用 `ctx.postSsrUrl` |
| 手拼 `#/p/`、`#/post/` 或自造链接 | 与系统路由不一致，易碎链 | 用 `ctx.postUrl(post)` / `ctx.postSsrUrl(post)` |
| 只做列表、不声明 `entries.post` | 点进文章掉回系统默认皮（体验割裂） | 声明 `entries.post`（见 §4.3B） |
| 主题根类未加 | 样式污染主应用 | 全部选择器挂 `.xx-root` |
| 忘记加 `settings.go` 白名单 | 控制台保存被拒 | §1.3.3 |
| 只交 SPA 组件、不交 `ssr.css` | 文章页不跟随主题 | 必修项 |
| 只交列表 + 文章页、内页只交了一部分 | 未交的内页掉回系统默认版式，整站气质割裂 | **五个内页与列表页同批交齐（无分期）**，见 §0.1 |
| 自行重排 `posts` | 与 SSR/RSS 顺序不一致 | 保持系统顺序 |

### C.2 交付质量类（v1.1 新增 · 全部由 §9.3 机械自检覆盖）

> 这 6 条的共性是：**构建不失败、console 不报警、代码看起来完全正常**，人眼极易漏检 —— 因此不要靠复查，跑脚本。

| 错误 | 后果 | 正确做法 |
|---|---|---|
| 页内锚点写进 `href="#x"` 或 `location.hash` | **宿主 hash 路由被篡改**，可能跳转/白屏；刷新后地址栏残留异常 hash | `button` + `scrollIntoView()`，全程不碰 hash。两种写法都要查：`href="#x"` 与 `:href="'#' + x"` |
| 文案写「热门 / 精选」而数据只有时间序 | 承诺契约中不存在的能力，用户会认为排序坏了 / 数据造假 | 文案只描述可证事实。**描述位置安全（头条 ✓），描述品质危险（精选 ✗）** |
| 类名用 `hot` / `rank` / `top` 表达时间序列表 | 命名与视觉双重误导后续维护者按"热度"心智改需求 | 按事实命名：`latest` / `recent` / `pinned` |
| `manifest.tokens` 与实际 `--th-*` 不一致 | 令牌台账失真，基于台账的自动化（后台可编辑项、文档生成、跨主题比对）全部建立在错数据上 | 逐项对齐；**属结构性遗忘，必须工具卡** |
| 模板有类名、CSS 无规则（悬空类） | 样式静默失效，当前靠继承"碰巧"正常，父级一动就塌 | 类名交叉比对，补齐或删除 |
| grid/flex 子项未加 `min-width: 0` | 长标题、搜索框撑破列宽，窄屏溢出 | 所有 grid/flex 子项显式 `min-width: 0` |

## 附录 F：宿主侧已知问题（非主题包缺陷 · v1.4.2 增补 2026-09-20）

> 本节记录**宿主/壳端**的已知问题，**不是主题包自身的缺陷**。审查"已开发未上线"的主题包时，若遇到下列现象，先对照本节判断是"包的问题"还是"宿主侧现状"，避免误判为交付不合格。

### F.1 市场装主题 title 显示为 id（展示层，不影响生效）

- 现象：通过应用中心/市场安装的主题，在后台主题下拉或 `theme_options` 里显示的是**主题 id** 而非 manifest 的 `name`；
- 归属：宿主未读市场包的 manifest `name` 回填展示字段（壳侧展示缺口）；
- 影响：仅展示文案，不影响主题实际生效与切换；**不是主题包缺陷**，提交主题时无需为此改包。

### F.2 本地 `install-zip` 对主题包先落盘后 422（安装路径缺陷）

- 现象：本地 `install-zip` 装主题包时，会**先把资产落盘、再因 `frontend_entry` 校验失败返回 422**（主题包本就无 `frontend_entry`，却被判缺）；
- 根因：`apps_market.go` 安装分支对主题包**无条件校验 `frontend_entry`**，且顺序在 `deployThemeAssets()` 落盘之后；
- 修复（壳侧待办）：把 `deployThemeAssets()` 移到 `frontend_entry` 校验**之后**，校验不过就不落盘；
- 对提交方的影响：主题包本身合规，此报错是壳侧安装路径问题；**不要因此往包里塞 `frontend_entry`**（会破坏声明式主题包的纯资产约定，见 §11）。

### F.3 SPA 主题"上线"门槛（最关键，决定"未上线"主题能否被看到）

主题双轨的"生效代价"不同（详见 §3.2 / §11），**"已开发未上线"≠"丢文件就能看"**：

| 轨 | 载体 | 上线动作 | 未做会怎样 |
|---|---|---|---|
| **SSR** `/blog`、`/{slug}` | `data/themes/<id>/{ssr.css,page.html}` | 丢文件即生效（运行时读，免编译免重启） | — |
| **SPA** `/app#/blog` | `web/src/themes/<id>/` Vue 组件 | **必须 `npm run build` + `go build` + 重启/重部署发行版** | 未编译的主题 id 会**静默回退 `default`**（不报错、看着"不生效"） |

- 结论：**SPA 主题"上线"= 构建并部署发行版**，不是把 `web/src/themes/<id>/` 丢上服务器就完事；审查"已开发未上线"的主题包时，应确认其是否随发行版构建部署过，而不是只看源码目录是否存在。
- 配套提醒：`web/src/themes/all.js`（或等价注册点）必须 `import` 该主题、`settings.go` 白名单须含其 id（见 §0.2），否则进入"孤儿目录"——既不在下拉、也不进构建产物（§0.2 已述，此处强调与"上线"的关系）。

### F.4 审查"已开发未上线"主题包的建议口径

1. 先看是 **SPA 主题**还是**声明式主题包（形态 B）**：形态 B 看 `ssr.css`/`page.html` 是否齐备即可判可用；SPA 主题还要确认构建部署状态（F.3）；
2. 遇"后台显示 id""安装 422"先对照 F.1 / F.2，确认不是宿主侧问题再判包不合格；
3. 主题包自身仍按 §9 验收清单 + §9.3 机械自检（`theme-lint.sh` 退出码 0）判定，本节不替代那些条目。

## 附录 G：导航 / 目录类主题建模（posts-as-entries · v1.4.3 增补 2026-09-20）

> 导航站（工具箱 / 资源目录 / 链接汇总）本质是「用博客当目录」。**不要把它当成脱离 AiKlog 的静态站**，也不要把样板里的模块当成硬编码装饰块。正确做法：每个公开文章 = 一个导航条目，全部走现有 `ctx.posts` / `ctx.tags` 契约，后台发一篇文章即上架一个条目，站长零代码维护。

### G.1 核心建模（每篇 = 一个条目）

| 导航条目要素 | 契约字段 | 用法 |
|---|---|---|
| 名称 | `file.name`（去 `.md` 派生标题） | 工具 / 站点名 |
| 彩色图标 / Logo | `file.cover` | 卡片图标；空值主题须确定性兜底（默认色块 / 首字母取色） |
| 一句话简介 | `file.excerpt`（空回退 `preview`） | 卡片描述 |
| 分类 / 类型 | `file.tags` 或 `path` 首段 | 分类网格与筛选依据 |
| 详情评测 | 文章正文（Markdown）+ `entries.post` 文章页 | 点击进入的详情页 |

- **容器**：做成**独立 theme id**，**不要往现有 Aurora 等主题里塞**导航模块，保持各主题单一职责。
- 工具「上架 / 下架」= 文章发布 / 草稿，天然支持；无需自建数据表。

### G.2 样板模块 → 契约落地（纠正「只能静态装饰」的误解）

- **分类网格**：用 `ctx.tags`（`[{ name, count }]`，**带真实数量**）渲染，不要硬编码分类与计数；也可从 `posts` 按 `path` 首段派生主分类。
- **统计区**：工具总数 = `posts.length`；各分类数量 = `tags[].count`；二者都是**真实数据**。需要「热门 / 浏览量」时，主题侧单独调 `GET /api/v1/public/blog/pv`（契约已存在，不在 `posts` 内），**不要臆造 `posts[].views`**。
- **彩色图标卡片**：`file.cover` 即图标；无封面用按 id 取色的确定性色块兜底，视觉丰富度不依赖硬编码。
- **工具详情**：`entries.post` 文章页，封面 + 摘要 + 正文评测全有，无需自建页面。

### G.3 两个契约缺口的官方口径（必须照此，不要自创）

1. **评分 / 星级 —— 契约无 `rating` 字段。**
   - 约定：**用标签承载**，给每个条目打形如 `★4.8` 的标签，主题读 `tags` 渲染星级。零契约改动、纯后台配置、可筛选。
   - 备选：详情页用 Markdown 星级展示（视觉有、不可排序 / 聚合）。
   - ❌ 禁止臆造 `posts[].rating` / `posts[].score`（§2.2 已列「不存在的字段」）。
2. **Newsletter 订阅 —— 宿主无公开订阅 API。**
   - 约定：**静态表单 + 外部接口**。主题只渲染 UI（输入框 + 提交按钮），提交动作指向站长自有或第三方邮件服务端点；**壳侧不做后端、不落库**。
   - 禁止臆造 `/api/v1/public/subscribe` 之类不存在的端点。

### G.4 给开发方的一句话口径

> 导航主题 = 独立 theme id + posts-as-entries 建模，所有条目 / 分类 / 计数都来自 `ctx.posts` / `ctx.tags` 真实数据；只有「评分」用标签约定、「Newsletter」用静态表单 + 外部接口这两处需按 G.3 处理，其余模块直接映射契约即可，**无需静态装饰、也无需脱离 AiKlog**。
