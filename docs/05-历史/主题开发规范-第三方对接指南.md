# AiKlog 博客主题开发规范（第三方对接指南）

> 版本：2026-09-14 · 适用仓库：AiKlog（web/src/themes/）
> 本文档由 elevated / parchment 两套主题的开发与审查实践整理而成，是第三方主题开发的**权威依据**。
> 第三方开发新主题时必须遵循本文档；与旧示例冲突时以本文档为准。

---

## 1. 主题目录结构与注册协议

```
web/src/themes/<theme-id>/
├── index.js          # 注册入口（必须）
├── manifest.js       # 元数据（必须）
├── <ThemeId>View.vue # 入口组件
└── style.css         # 主题样式（必须在组件里 import）
```

### 1.1 index.js —— 正确写法（模块加载时直接注册，禁止回调式）

```js
import { defineAsyncComponent } from 'vue'
import manifest from './manifest.js'
import { registerTheme } from '../index.js'

const theme = { ...manifest, entry: defineAsyncComponent(() => import('./XxxView.vue')) }
registerTheme(theme)
export default theme
```

❌ 错误：`export default function(app, { registerTheme }) {...}` 回调式 —— 永远不会被调用。

### 1.2 manifest.js —— 字段名协议（大小写敏感）

```js
export default {
  id: 'elevated',                 // kebab-case 唯一标识
  title: '高端暗色 Elevated',      // ✅ title（不是 name/nameZh），切换条显示它
  desc: '一句话描述',              // ✅ desc（不是 description）
  version: '1.0.0',
  dataSources: ['blog'],          // 通用博客主题固定此值
  dataScope: 'shared',            // 公开主题固定 shared，禁止 library
  ui: { themeSwitcher: true },    // 声明「主题自己在页头渲染了切换器」，宿主不再补悬浮版（见 §8.4）
}
```

### 1.3 接入系统（共 3 处，缺一不可）

1. 在 `web/src/views/BlogView.vue` 顶部追加一行静态 import：
   ```js
   import '@/themes/<theme-id>' // 注册 xxx 主题
   ```
2. 控制台「博客管理 → 站点设置 → 交互版主题」下拉**自动出现**新主题
   （BlogManage 从注册表 `listThemes()` 动态渲染，无需改下拉）。
3. ⚠️ 唯一需要手动同步的是服务端白名单，见 §1.4。

### 1.4 ⚠️ 服务端白名单（最容易漏的一步）

新主题 id 必须同步加进 `server/internal/handler/settings.go` 的 `blog.theme` 白名单，
否则控制台站点设置保存时会被 `SETTING_INVALID` 拒绝：

```go
case "", "default", "aiklog", "minimal", "docs", "paper", "elevated", "parchment":
```

主题生效机制：`GET /api/v1/public/site` 返回 `site.theme`（settings 表 `blog.theme` 键，默认 `aiklog`），
BlogView 以它为准激活主题 —— **localStorage 不是权威来源**。

## 2. 数据契约（inject，不是 props）

BlogView 渲染主题时 `<component :is="entry" />` **不传任何 props**。数据一律：

```js
import { inject, computed } from 'vue'
const ctx = inject('themeContext')
const posts  = computed(() => ctx.value.posts  || [])
const tags   = computed(() => ctx.value.tags   || [])
const siteName = computed(() => ctx.value.siteName || '爱库录')
const postUrl  = ctx.value.postUrl            // 单篇地址生成器
```

### 2.1 posts 字段真实结构（逐字段核对，禁止臆造）

```js
{
  token: '...',              // 公开访问令牌
  path: '分类/文件名.md',
  preview: '纯文本摘要',      // 已由服务端生成（AI 摘要/截断）
  file: {
    name: '文件名.md',
    slug: '',                // 当前恒为空串，URL 用 path 派生，不要依赖它
    updated_at: 1726000000000, // 毫秒时间戳
    size: 12345,
  },
}
```

❌ 不存在的字段（历史上出现过，全部是错的）：`id` / `title` / `summary` / `cover` / `readTime` / `views` / `tags`（单篇标签）/ `contentHtml` / `created_at`（用 `updated_at`）。

### 2.2 标题/分类的派生方式（与系统 SSR 保持一致）

```js
// 标题：去扩展名 + 取末段（.md 和 .markdown 都要处理）
name.replace(/\.(md|markdown)$/i, '').split('/').pop() || '无标题'
// 分类：path 首段；无 '/' 则归「未分类」
```

### 2.3 文章打开方式 —— 必须跳 SSR 页（SEO 双轨模型的根契约）

```html
<a :href="postUrl(post)">…</a>   <!-- 渲染为 /{文件名去扩展名} 或 /blog/{…} -->
```

❌ 禁止在主题内做 SPA 文章视图/内部渲染：契约不提供正文 HTML，且会绕过 SSR SEO。
同理评论、相关推荐等依赖正文的功能**不要做**（或等系统层提供数据后再做）。

### 2.4 tags 能力现状（重要）

协议声明 `tags: Array<{name, count}>`，但 **BlogView 当前从未填充（恒为空数组）**。
系统层标签过滤（`/blog?tag=xxx`）也**尚未实现**。因此主题端规范：

1. 标签云区块必须 `v-if="tags && tags.length"` 包裹（恒空时自动隐藏，不占位）；
2. 遍历对象是 `{name,count}`，必须写 `{{ t.name }}`（写 `{{ t }}` 会渲染成 `[object Object]`）；
3. 渲染为非链接 `<span>`，**不要**输出 `?tag=` 死链；系统层实现后再改回 `<a>`。

## 3. 服务端交互接口约定

### 3.1 AI 问答（可选能力）

- 端点：`POST /api/v1/public/blog/ask`
- 请求：`{ "question": "..." }`
- 响应：**`{ "reply": "..." }`** —— 读 `reply`，❌ 不是 `answer`
- **必须处理 HTTP 429 限流**（每 5 分钟 8 次），给用户友好提示
- 输入为空时禁用按钮，请求中显示 loading

### 3.2 归档/统计

从 `posts` 自行派生（按 `updated_at` 分组年月、计数），不要指望接口提供。

## 4. 样式规范

1. **style.css 必须在入口组件里显式引入**：`import './style.css'`（否则整页无样式）。
2. **Reset 必须完整**：后代元素通配符不能漏 ——
   ```css
   .xxx-root, .xxx-root *, .xxx-root *::before, .xxx-root *::after {
     margin: 0; padding: 0; box-sizing: border-box;
   }
   ```
3. **作用域隔离**：所有选择器挂在主题根类下（如 `.elevated-root …`、`.parchment-root …`），
   CSS 变量统一 `--th-*` 或主题专属前缀，禁止污染全局。
4. **语义化标签**：站名用 `<div>`/`<p>`，不要拿 `<h1>` 放站名（文章页 SSR 才是 h1 的家）。
5. **删除死 CSS**：组件里没有对应模板的规则必须删掉（历史教训：Parchment 曾带 ~350 行
   文章页/分页/评论死代码，误导后续维护）。
6. 配色贴设计稿时逐值核对（渐变、噪点层、暗/亮底适配），亮色主题的分类占位渐变
   必须用低饱和同底色系，禁止把暗色渐变直接搬过来。

## 5. 构建与部署流水线

```bash
# 前端
cd web && npm run build
# 产物拷入 server 嵌入目录（覆盖前先清空）
rm -rf server/internal/handler/webdist && mkdir -p server/internal/handler/webdist
cp -r web/dist/* server/internal/handler/webdist/
# 后端单二进制
cd server && go build -o bin/aiklog ./cmd/aikmap
# 服务器重启（演示站 183.16）
pkill -x aiklog; cd /opt/aiklog && setsid nohup ./bin/aiklog -addr 127.0.0.1:8780 \
  -db data/aikmap.db > aiklog.log 2>&1 < /dev/null &
```

切换主题：控制台 → 站点设置 → 博客主题（写 `blog.theme`），或
`PUT /api/v1/admin/settings {"key":"blog.theme","value":"<id>"}`。

## 8. 页面级契约（列表 / 文章 / 标签 / 分类 / 归档 / 搜索 / 404 与主题切换器）

> 背景：此前规范只约束了「主题入口组件渲染列表页」，导致**文章页、标签页等页面样式不跟随主题**。
> 本节把**所有公开页面的职责边界**钉死，第三方主题据此一次性做全，避免「列表好看、点进去变样」。

### 8.1 渲染双通道总览

| 页面 | 渲染方 | 主题样式来源 | 系统实现状态 |
|---|---|---|---|
| 列表 `/blog`（SPA 交互版） | 主题入口组件（BlogView→entry） | 主题 style.css（SPA） | ✅ 已上线 |
| 列表 `/blog`（SSR） | `public_html.go` | `blogThemeCSS(id)` + 外置 `ssr.css` | ✅ 已上线 |
| 文章 `/{slug}`（SSR） | `public_html.go` | `blogThemeCSS(id)` + 外置 `ssr.css` | ✅ 已上线 |
| 文章（SPA 内 ReadView） | `ReadView.vue` | **未随主题**（系统层旧兜底，后续统一到 SSR） | ⚠️ 不考核 |
| 标签 `/blog?tag=x` | 未实现 | — | ❌ 系统层待做 |
| 分类 `/blog?cat=x` | 未实现 | — | ❌ 系统层待做 |
| 归档 `/blog?archive=YYYY-MM` | 未实现 | — | ❌ 系统层待做 |
| 搜索 `/blog?q=x` | 未实现 | — | ❌ 系统层待做 |
| 404 | 未实现 | — | ❌ 系统层待做 |

SEO 双轨模型下，**文章与列表的规范入口是 SSR 页**（`/{slug}`、`/blog`），SPA 仅用于登录态交互。
因此「文章页样式跟着主题走」的落地点是 **SSR 的 `blogThemeCSS`**，而非 SPA 主题组件（§8.2）。

### 8.2 文章页如何跟随主题（第三方必做：投放 `ssr.css`）

内置主题（aiklog / default / minimal / docs / paper / elevated / parchment）的 SSR 气质样式已写死在
`server/internal/handler/public_html.go` 的 `blogThemeCSS()` 分支里。**第三方主题不要改 Go 源码**——改用外置文件机制：

1. 在服务器 `data/themes/<你的id>/` 下放两个文件：
   - `manifest.json`：`{ "title": "主题中文名" }`（SSR 下拉与页头显示用）；
   - `ssr.css`：覆盖 CSS 变量 `--ink / --ink2 / --ink3 / --paper / --line / --jade / --card / --font-d`，
     以及系统 SSR 类名 `.wrap / header.site / .list li / article h1 / .body *` 的微调（模板见 `blogHTMLTmpl`）。
2. 系统加载：`blogThemeOptions()` 自动把 `data/themes/` 下的目录加进 SSR 页头下拉；
   `blogThemeIDFor()` 支持 `?theme=<id>` 预览；`blogThemeCSS()` 优先读外置 `ssr.css`（256KB 上限，按 mtime 缓存）。
3. 列表页与文章页**共用同一份 `ssr.css`**，所以一次投放即「列表 + 文章」全跟随主题。

⚠️ `ssr.css` 只应覆盖系统 SSR 模板已有的类名 / CSS 变量（见 `public_html.go` 的 `blogHTMLTmpl`），
不要臆造不存在的钩子；正文由系统用 goldmark 渲染进 `.body`，主题只调字体 / 配色 / 代码块。

### 8.3 标签页 / 分类页 / 归档页 / 搜索页 / 404（占位约定）

系统层尚未实现这些页面。第三方主题当前应：
- 在列表页预留「标签云 / 分类导航」区块（沿用 §2.4 的 `v-if="tags.length"` 规则，系统层实现 `?tag=` 后自动生效）；
- **不要**自行输出 `/blog?tag=` `/blog?cat=` 死链（会 404）。系统层实现后，主题把标签云项改回
  `<a :href="postUrl + '?tag=' + encodeURIComponent(t.name)">` 即可；
- 404：系统层补全前，未知 slug 走 SSR 兜底（返回站点默认主题样式 + 提示），主题无需单独处理。

### 8.4 主题切换器（SPA 公开页右上角 + SSR 页头下拉）

- **SPA 公开页**（`/app#/blog?view=public`）：每个内置主题在自己的页头 nav（RSS 旁）渲染
  `<ThemeSwitch />`（inline 模式）。主题需在 manifest 声明 `ui: { themeSwitcher: true }` 作为「自带切换器」的承诺；
  **未声明 / 未渲染的主题，宿主（BlogView）自动在右上角补一个悬浮 dock 版**，保证任何主题都能换肤。
- 切换结果写 `localStorage('aiklog.theme.override')`，优先级高于站点设置；站长登录后可「设为站点主题」
  （`PUT /api/v1/admin/settings {"key":"blog.theme","value":"<id>"}`），变成全站默认。
- **SSR 页**（`/blog`、`/{slug}`）：页头有原生 `<select name="theme">` 下拉，提交即 `?theme=` 预览，
  选项来自 `blogThemeOptions()`（内置 + `data/themes` 外置目录）。

### 8.5 第三方主题「页面级」验收清单（追加）

- [ ] 投放 `data/themes/<id>/manifest.json` + `ssr.css`，SSR `/blog` 与 `/{slug}` 配色随主题变化

- [ ] 若自带切换器：manifest 声明 `ui.themeSwitcher: true` 且页头渲染 `<ThemeSwitch />`
