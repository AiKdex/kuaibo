## 一、产品定位与主张

### 1.1 主张

| 层 | 文案 |
|---|---|
| **主句** | 目录即站点，文件即文章 |
| **副句** | 拖拽即发、语义检索、双链互文——自部署 AI 知识库博客 |
| **机制** | 笔记与资料在库里整理，目录投影成公开站；数据在自己手里 |
| **品类** | 自部署博客 / 知识库博客（对标 emlog、Typecho，多一个知识引擎） |

**不使用：**「拖一个 Markdown 就是一个公开站」（一文件 ≠ 一站）。

### 1.2 核心理念

```
用户操作：把文件放进「博客」目录 → 自动成为公开文章
用户感知：写 → 发 → 读者看 → 评论 →（可选）AI 问答
技术底座：文件引擎 + 索引引擎 + AI 网关 + 事件总线 + 插件系统
```

**知识库是后台引擎，不是前台卖点。**  
读者看到的是干净博客；管理员侧才有文件库、标签、语义检索、设置。

### 1.3 差异化一句话

> emlog 是「写博客的工具」，爱库录是「让知识自然长成公开站的系统」。

| 传统博客 | 爱库录 |
|---|---|
| 先有想法，再进后台写一篇 | 先有笔记/文件，再整理进目录对外 |
| 搜索靠关键词 | 关键词 + 语义 |
| AI 外挂插件 | AI 在引擎层（摘要/向量/推荐） |
| PHP + MySQL | 单二进制 + SQLite |

## 二、目标用户与场景

| 用户群 | 场景 | 付费意愿（远期） |
|---|---|---|
| 技术博主 | 技术笔记、代码片段、学习整理 | 中 |
| 知识工作者 | 读书笔记、行业观察、研究整理 | 高 |
| 独立创作者 | 个人品牌、作品与内容沉淀 | 中 |
| 小团队 | 团队博客 / 产品文档一体 | 高 |
| 自部署爱好者 | 要数据主权、要可审计 | 中高 |

**典型故事：**

1. 作者在本地/Obsidian 写笔记 → 拖进爱库录博客目录 → 公开站更新、RSS 更新  
2. 读者按意思搜索「那篇讲目录即站点的」→ 语义命中  
3. 文章之间 `[[双链]]` 互跳；侧栏/正文下由插件挂评论、元信息、相关推荐  

**非目标（精简发行不做）：** 采集爬虫、IM 网关、多租户 SaaS 计费（后续版本另议）。

- **存储层隐藏**：博客树不在普通文件管理器裸奔，只在博客管理

## 四、技术架构

### 4.1 分层

```
接口层   公开博客 · 控制台 · RSS · OpenAPI 子集 · 插件 API
应用层   博客管理 · 发布 · 检索 · 插件 · 主题 · AI
内核层   文件引擎 · 索引引擎 · 事件总线 · 插件运行时 · 配置
存储     SQLite（WAL）+ 本地文件树（防路径穿越）
运行时   Go 单二进制（前端 go:embed）
```

### 4.2 精简发行依赖

| 保留 | 裁剪 |
|---|---|
| modernc.org/sqlite | bogdanfinn/tls-client 及间接依赖 |
| vue / pinia / vue-router | echarts（图谱） |
| vditor / marked / hljs / dompurify | 采集、IM、情报频道 |

### 4.3 关键契约

- 博客插件：manifest + `registerBlogPlugin` + 四挂载点  
- 主题：`registerTheme` + `dataSources:['blog']` + `dataScope:'shared'`  
- 投递：`POST /api/v1/blog/posts`（外部采集线 Aikdex 用）  
- 公开只读：`/public/posts` `/public/site` `/public/comments` `/blog/feed.xml`  
- OpenAPI：`docs/openapi-public.yaml`（blog / public / auth）

## 五、竞品对比与市场评估

### 5.1 直接竞品

| 系统 | 运行时 | DB | AI | 自部署 | 博客体验 | 知识库底座 |
|---|---|---|---|---|---|---|
| emlog | PHP | MySQL | 外挂/无 | ✅ | ⭐⭐⭐⭐⭐ | ❌ |
| Typecho | PHP | MySQL | 无 | ✅ | ⭐⭐⭐⭐ | ❌ |
| WordPress | PHP | MySQL | 插件 | ✅ | ⭐⭐⭐⭐⭐ | ❌ |
| Ghost | Node | MySQL | 弱 | ✅ | ⭐⭐⭐⭐⭐ | ❌ |
| Hugo | 静态 | 文件 | 无 | ✅ | ⭐⭐⭐⭐ | ❌ |
| **爱库录** | **Go 单二进制** | **SQLite** | **内置底座** | ✅ | ⭐⭐⭐⭐（打磨中） | ✅ |

### 5.2 间接竞品（AI 知识库）

Khoj / RAGFlow / AnythingLLM 等：有检索无「可运营的公开博客门面」。  
爱库录补的是 **发布层 + 博客体验**，不是再做一个企业 RAG。

### 5.3 竞争位置

```
博客体验高 ↑     emlog · WordPress · Ghost
                  ★ 爱库录（目标：体验接近 + AI 底座）
              Hugo              Khoj（纯知识库）
         ───────────────────────────→ AI 能力强
```

### 5.4 市场评估（务实）

| 判断 | 说明 |
|---|---|
| **主市场** | 中文自部署博客（emlog/Typecho 用户升级心智） |
| **切口** | 「会写 Markdown / 有笔记库」的人，要公开站且要数据主权 |
| **TAM 叙事** | 千万级个人站点存量中，技术/知识向子集 |
| **现实份额** | 插件/主题生态远弱于 WP/emlog；靠「底座差异 + 极简部署」单点突破 |
| **增长逻辑** | 样板房可访问 → 文档可装 → 内置插件证明协议 → 应用市场 |
| **变现（远期）** | 付费主题/插件、应用市场分成、托管版/企业支持（**当前阶段不做收费墙**） |

**结论：** 不做「又一个 WP」；做 **自部署时代带知识引擎的博客**。体量小但差异清晰，适合先样板房后生态。

## 九、部署方案

### 9.1 推荐规格

| 档 | 配置 | 场景 |
|---|---|---|
| 最低 | 1C 1G 20G | 个人试用、低流量 |
| 样板房 | 2C 2G+ | 公开站 + 插件 |
| 团队 | 2C 4G | 多写手、大库、AI 读 |

### 9.2 拓扑（样板房实测）

```
Internet → Nginx (80/443, LE)
              ├─ /          产品落地页（静态）
              ├─ /media/    配图静态
              └─ /          proxy → 127.0.0.1:8780 aiklog (systemd)
                                └─ SQLite + data/files
```

### 9.3 最小步骤

1. 放置二进制 + 数据目录，用户 `aiklog`  
2. `AIKMAP_ADMIN_PASSWORD=… ./aiklog -addr 127.0.0.1:8780 -db ./data/aiklog.db`  
3. systemd `Restart=on-failure`，`ProtectSystem=strict`  
4. Nginx 反代 + `X-Forwarded-Proto`（Cookie Secure）  
5. certbot / acme.sh 签证书  
6. 备份：整库 `aiklog.db` + `data/files`（**含博客树**）  

### 9.4 升级

- 替换二进制 → schema migrate → 配置在 DB 自动保留  
- 回滚：保留上一版二进制 + 快照 db

## 十二、风险与规避

| 风险 | 等级 | 规避 |
|---|---|---|
| 生态冷启动 | 高 | 内置 5+ 插件证明协议；文档 + 示例 |
| SPA 对 SEO 弱 | 中 | sitemap、meta、必要时 prerender |
| 用户觉得「不需要知识库」 | 中 | 博客 UI 优先；底座隐形 |
| SQLite 多写 | 低（个人博客） | WAL；多作者再议 Postgres |
| AI 外呼失败 | 中 | 基础发布不依赖 AI |
| 默认口令/公网裸奔 | 高 | 样板房改密、限登录、HTTPS |
| 与 Aikdex 混线 | 中 | 文档写死边界：系统 vs 内容 |
