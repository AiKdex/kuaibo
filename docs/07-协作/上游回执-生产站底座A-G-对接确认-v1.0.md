## 二、三项待确认 —— 逐项答复

### 1. 出站多平台分发归属

**结论：不出底座模块；纳入 Agent Tools 生态（v2 能力插件优先），ChannelView 前端由壳侧自持。**

- 理由：与采集对称——"弄到内容"走采集 tools（D），"发出去"走发布 tools，内核不硬编码任何平台，天然多平台可扩展、可商业化（发布 tool 可免费/付费上架）。
- 内核侧若后续需要"出站通道管理"（多账号凭证加密存储 + 发布队列 + 失败重试 + 频率控制），列为下一轮底座 **P1**，届时以 `CoreModules.Channel` 新字段注入，壳侧零签名改动（需人工核对字段清单补 Routes 门控）。
- 当前壳侧可先行：复用已有定时发布 + 文章公开 API，发布 tool 按 AgentTools v1 规范先行注册即可。

### 2. AgentTools v2 运行时时间表

**结论：v2 随商业化 v0.2（Entitlement 签发服务 + 正式付费货架）一并排期，暂无硬日期；v1 工具 v2 时代完全兼容，AiKlog 按 v1 先行不返工。**

- v1 = 宿主进程内注册执行的 Go 工具（manifest + zip + sha256 + 统一安装管线）——现行。
- v2 = 声明式能力/UI 插件（`kind=ui|capacity`，不执行远程代码）；**复用 v1 的市场协议**（manifest/安装/货架/Entitlement 全链路），仅新增 `kind` 字段与宿主侧能力钩子（权限申请、文件系统边界、UI 挂载点）。
- 关键差异一句话：v1 是"代码进宿主跑"，v2 是"声明进宿主装，能力宿主提供"。
- 过渡承诺：官方索引将加 `api_version` 提示位；v1 条目在 v2 货架中保持可安装，不强制迁移。
