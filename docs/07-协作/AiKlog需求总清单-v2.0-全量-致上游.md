## 三、本轮新增 / 继续提交的上游需求（11 项）

### 3.1 结构性缺口：`CoreModules` 接入路径 【需上游给契约】

**背景**：AiKlog 是主系统的**早期 fork**，`handler.New(...)` 采用**位置参数注入**，**不存在 `handler.CoreModules` 结构体**。后果：上游 A-G 之后的底座模块（Sources / Collector / WebDAV / Digest / Inbox / Review / Org / Channel）在 AiKlog **无法条件式注册 → 静默不可用**（这正是 2.2–2.6 各项"后端已备、壳侧待接"在 AiKlog 侧其实接不上的根因）。

**需要上游**：

1. `handler.CoreModules` **字段终版清单** + `Routes()` **门控矩阵**（哪个字段非 nil 注册哪些路由）——用于我方核对，防新模块静默遗漏；
2. 面向「**老 fork 增量接入**」的最小迁移指引：或直接给 `New(db, cfg, ..., mods CoreModules)` 的迁移 diff 示例；
3. **确认**：AiKlog 侧已自建 `ai.Registry` + `reg.Register` 工具注册机制（当前注册 6 个工具：search_files / read_file / dedup_files / batch_tag_files / batch_organize / batch_rename），与上游工具机制同形——是否可直接对齐、无需重复造。

---

### 3.2 采集工具构造器 【需上游给源码】

**背景**：上游《采集 tool 注册矩阵》（9/19 回执）要求 AiKlog 注册 `tool_web_clip`；但 AiKlog fork 中**不存在**该工具的构造器（仅有 3.1 所列 6 个本地工具）。

**需要上游**：

- `ai.NewWebClipTool(...)`、**WebDAV 导入**、**RSS 导入** 三个工具的**构造签名 + 源码/包**（可直接移植）；
- 其依赖端点（收件箱 / 草稿态 `blogPostCreate`）的契约确认；
- 《AgentTools开发规范》补「官方工具注册矩阵」章节（上游已承诺）。

---

### 3.3 主题宿主能力契约：options_schema 自动表单 + theme_settings 下发 + SSR 注入点 【需上游给契约】

**背景**：主题规范 v1.4 §7.4 明确要求宿主「按 manifest `options_schema[]` 声明**自动渲染站长设置表单**并存储下发」，运行时消费 `/public/site` 的 `theme_settings`，SSR 经 `{{.ThemeVars}}` 注入 CSS 变量。**AiKlog 宿主尚未实现**：`/api/v1/public/site` 目前只返回主题列表（`theme_options`），**无 `theme_settings`**；无 schema 表单渲染组件。

**需要上游确认**：主系统是否**已实现**该机制？

- **若已实现** → 请给**端点 / 存储 / 下发契约 + 参考实现**（表单渲染组件、`theme_settings` 序列化字段、SSR 变量注入点），AiKlog 直接移植；
- **若未实现** → 请列入下一轮底座，与「主题市场闭环」一并排期。

> 这是**主题生态闭环的前置**：规范已向第三方主题承诺该能力，宿主不实现则主题的 `options_schema` 声明形同虚设。

---

### 3.4 市场卡片图片化 + `demo.html` 在线预览 【需上游给契约】

**背景**：主题规范 §0.4 要求主题包内附 `preview/cover.png`（整页截图 ≥2 张，PNG/JPG/WebP）+ `preview/demo.html` + `README.md`（主题介绍）+ manifest `description`（≤60 字）；同时写明「宿主侧市场卡片渲染封面图与在线预览的支撑**随后续版本提供**」。

**需要上游**：

- 市场索引 / 卡片对 `preview/*` 材料的**字段约定**（`cover` / `screenshots[]` / `demo_url` 等）；
- 宿主渲染契约：卡片封面图取址规则 + `demo.html` **在线预览实现口径与安全边界**（是否 iframe 沙箱、外链白名单）。

---

### 3.5 结构化分类树数据源 【需上游确认契约】

**背景**：主题规范 §7.4 允许多级分类链接 `#/blog/cat/a/b`，但要求「**在宿主透出结构化分类树数据源之前，主题不要自行从 path 推断构建多级导航树**」。AiKlog 现状：管理端已做递归子目录（`blog_manage.go`），公开轨仅按 path 前缀过滤，**未向主题透出结构化分类树**。

**需要上游**：分类树的**字段形态**（cat 树 JSON：id / name / path / children / count）与**注入点**（`themeContext` 还是独立公共 API）。

### 3.9 增量 / 混合渲染（生产站地基③） 【需上游确认】

**背景**：《生产站应用场景》判定「**全量 SSG 导出扛不住千级条目站**」，需增量/混合渲染；这是资源站/导航站/聚合站（T0/T1 梯队）能否承载量级的关键地基。

**需要上游**：确认主系统是否**已具备或已规划**「增量渲染 / 按需渲染 / ISR 类」能力；若在路线图，请给出**口径与排期**（若无，我方评估壳侧自建）。

### 3.10 投稿（UGC 入口）与审核队列 【需上游确认】

**背景**：生产站（资源/导航/企业站）需要**前台投稿表单 + 审核队列**（投稿→待审→发布）。AiKlog 现状：**有评论（`/public/comments`，访客默认待审），无投稿端点**；上游有 `review` 模块（评分/评价语义）。

**需要上游**：确认 `review` 模块是否覆盖「投稿 + 审核」，或另有投稿契约；若需新增，请给字段与状态机口径。

### 3.11 自动内链 / 孤岛提醒的统一契约 【需上游确认】

**背景**：「**改一处全站更新**」是生产站的核心卖点，依赖自动内链 / 相关文章 / 孤岛提醒。AiKlog 已自建双链 / 断链检测（`kb.go` / `impex.go` / `indexer.go`）。

**需要上游**：确认上游是否有统一的「自动内链 / NodeLink」契约可对齐（避免壳侧自建与上游语义**两套并存**），特别是与 A-G 的 E 项（链接健康检查）如何分工。
