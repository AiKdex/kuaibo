## 2. 设计决策

- **B10-1 内容类型过滤「只加一个开关维度」而非改公开列表根逻辑**：分享任意目录时附件本身就是被分享内容，不该被静默隐藏；是否「只列文章」由调用点显式决定（`articlesOnly`），管理轨与分享查看保持不过滤。
- **B10-1 判定顺序**：`content_state.node_type` 显式声明优先（post/article/page=文章；attachment/asset/media/image=附件）→ 未声明按 `isTextContent(mime)` 兜底（与评论收录同判据）；`blog.list_attachments=true` 一律放行（恢复旧行为，适合整目录图集）。
- **B10-2 根因**：生产是 nginx → 127.0.0.1:8780 明文反代，后端 `r.TLS` 恒 nil，此前 RSS 自算 scheme 会把链接写成 `http`。统一走 `publicBaseURL`（读 `X-Forwarded-Proto`/`X-Forwarded-Host`），与 sitemap / SSR 页面同源。RSS 链接形态对齐 sitemap 与收录回指（`/{slug}`），对订阅器与搜索引擎更友好。
- **B10-3 按身份限流而非 IP/全局**：绑定码是 6 位短码，真正暴力面是「某 IM 身份反复试码」；按身份锁既挡暴力又不会因共用出口误伤无关用户。锁定期内直接拒绝、**不消耗任何码**；绑定成功即删行清零。

## 3. 踩坑（已修）

- **B10-3 `BindLockState` 懒清理误清零导致锁永不触发**：原条件 `locked_until != 0 || fail_count != 0` 在「从未锁定、仅累积失败」时也会把 `fail_count` 清零 → 失败计数永远到不了阈值。改为**仅在「曾锁定且已过期」时清零**（`locked_until != 0 && locked_until <= now`）。单测抓出，已修。
