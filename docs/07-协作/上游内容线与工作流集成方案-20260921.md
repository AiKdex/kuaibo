## 1. 结论

这条线与本壳契合度**远高于**协作层，原因是零件级可搬：上游的内容能力大多挂在
**同一套内容模型**（`files` + `content_state` + `tags`）与**同一套内核接口**（`ai.Registry` 工具注册表、`engine/bus`）上，
而这两样我们都有。因此不存在"换范式"的问题，是**加端点 + 加表 + 加节点**的增量工程。

一句话：**内容/工作流 = 增量集成；协作层 = 范式错配；论坛 = 自研但零件齐**。

### ✅ B2 内容工作流引擎（已完成）

- **上游**：`handler/workflow.go`(569 行) + `workflow_defs` / `workflow_runs` 表 + 4 端点。
- **它到底是什么**：不是"审批流"，是**步骤链引擎**——
  触发器 `im_command`；步骤类型 `空`(注册表步骤函数) / `tool`(内核工具注册表 `reg.Exec`) /
  `llm`(模型调用) / `condition`(条件路由，`when` 匹配 `$prev`) / `delay`(≤60s)；
  参数模板 `$msg.*` / `$prev.*` / `$ctx.*`；失败策略 `abort|skip|retry`。
- **为什么契合**：本壳定位是「IM 入口 → 博客引擎 → 应用中心」，而引擎的 `Type=tool`
  **直接走内核工具注册表**——我们 `ai.Registry` 已有 9 个工具（含 `web_clip` 采集）。
  接上之后，`采集 → AI 整理 → 出草稿 → 发布` 就是一条可编排、可由 IM 指令触发的流水线。
- **本壳落地**（`handler/workflow.go`）：
  - 引擎全量移植：触发器匹配 / 模板求值 / 条件路由 / delay / on_fail / `workflow_runs` 幂等闸门。
  - **步骤注册表换成内容侧**（上游内置的是 `tool_im_*`，依赖其 `im_tools.go`，本壳无此组件）：
    `blog_create_draft`（建草稿）/ `blog_search`（检索）/ `blog_set_tags`（打标签）/ `blog_publish`（发布）。
    注册表是开放的：新增步骤只需加一个 `wfStepFunc`，**不动引擎**。
  - 官方内置 3 条：`/wf-draft`（指令建草稿）、`/wf-polish`（AI 整理成稿）、`/wf-find`（检索内容）。
  - 4 端点与上游同构（便于 workflow 定义跨壳搬运）：
    `GET|POST /api/v1/workflows`、`POST /api/v1/workflows/{id}/run`、`DELETE /api/v1/workflows/{id}`。
- **两处必须改造的地方（含理由）**：

  1. **触发前缀要命名空间化**。上游让每个 workflow 占一个全局前缀（其内置用了 `/publish`），
     而本壳 `/publish`、`/draft` 已被既有 IM 指令占用 —— 即 **"前缀全局唯一"这个假设在本壳不成立**，
     且应用中心装多个 workflow 包时前缀必然互撞。故本壳：内置前缀一律 `/wf-*`，
     并另给统一入口 **`/wf <id> [正文]`** —— 自定义与市场安装的工作流走这条，不依赖前缀唯一性。
  2. **`llm` 步骤必须防"降级文案污染"**。上游用 `a.ai.Ask`；本壳 gateway 是 `ChatJSON`，
     且**未配置模型时返回降级文案而非 error** —— 照搬会把「AI 服务未配置…」当成文章正文写进草稿。
     故 `llm` 步骤先判 `ActiveProvider("ai.llm")`，为空即失败。**已实测验证**（见 §5）。
- **另修上游一处执行器缺陷**：上游 `on_fail=retry` 时无条件回调 `fn()`，而 `fn` 只在「注册表步骤」
  分支被赋值 —— `tool` / `llm` / `condition` / `delay` 步骤配 `retry` 会 **nil panic**。
  本壳改为**整步重入**（`wfExecStep`），任何步骤类型都能正确重试。
- **IM 接入**：`im/intent.go` 加 Layer 0 命名空间（`/wf`），`imDispatch` 挂 `IntentWorkflow`；
  并在 `IntentAgent` 之前探测 workflow 的 `im_command` 前缀（站长自定义指令如 `/collect` 可用）——
  既有指令在 Layer 1 已优先命中，不会被抢。幂等键取 `im:<platform>:<msg_id>`，与 `im_ingest` 同粒度。

### ✅ B3 内容引用与归因（评论收录，已完成）
- **上游**：`handler/ingest.go`(592 行)、`ingest_groups` / `ingest_items` 表、7 端点。
- **能力**：`POST /ingests/quote` 原文照录 + 归因区块**直接写入正文**；`POST /ingests/fuse-draft` AI 产融合草稿（**不碰正文**）；
  `POST /ingests/{id}/accept` 采纳才写正文；`DELETE /ingests/{id}` 按锚点**区块级撤销**；
  `GET /ingests?file_id=` 回查 / `GET /ingests/pending` 跨文章待办 / `GET /ingests/my-count` 我的被收录次数。
- **为什么契合**：这是**内容把外部输入沉淀为正文**的唯一通道——博客的评论、论坛的回帖、采集的线索，
  都能带署名与回链「长」进正文，且**只 append 不 mutate**（既有人工内容一字不动，撤销只摘自己那一段年轮）。
  归因区块模板写死（署名 + 日期 + 回指链接三要素，不可关闭），被收录者收站内通知 → 荣耀激励闭环；
  `my-count` 可在个人页做声誉展示。与"分发只走应用中心"的定位不冲突。
- **本壳改造点（6 处，均有理由）**：
  1. **评论取本壳 `comments` 表**（上游另起 `blog_comments`）：正文列 `body`、归属列 `file_id`；
     作者名 = 登录用户 `users.display_name`，访客回落 `comments.guest_name`（上游用冗余列 `author_name`）。
  2. **守卫用 `blogAuthorOnly`**（owner/admin/作者白名单）+ `isBlogPostFile` 校验目标确为博客文章
     （上游按 `files.owner_id == uid` 判，在本壳「文章统一挂博客目录」的形态下过窄）。
  3. **回指链接用本壳公开文章地址** `{origin}/{slug}#comment-{id}`（上游是 SPA 深链 `#/p/blog?slug=…`）：
     与 sitemap/JSON-LD 公布的地址保持一致；SSR 主题若渲染评论锚点，加 `id="comment-{id}"` 即可直达。
  4. **文本判据收紧为结构化白名单**（见 §8）：上游 `strings.Contains(mime,"xml")` 会把 `.docx`
     （open**xml**formats）当正文读进来照录 → 写回即损坏二进制。收录侧改白名单，且是
     `service.isTextMime` 的**子集**，保证「读得过 → 也写得回」。
  5. **AI 步骤先判 `ActiveProvider("ai.llm")`**：本壳 `ChatJSON` 未配置时返回降级文案而非 error，
     不判会把「AI 服务未配置…」当正文写进草稿（与 B2 的 `llm` 步骤同一坑）。
  6. **通知走 `service.NotifyStore.AddUser`**（统一 payload 契约），不直接 INSERT `notifications`。
- **另新增可配置项**：`POST /api/v1/blog/posts/meta` 支持 `growth`
  （`allow`（默认）| `collect` | `auto` | `frozen`），写入 `content_state.growth`；
  非法值回落 `allow`；`frozen` 时收录端点返回 `INGEST_FROZEN`。缺省即 `allow`，旧数据零迁移。
- **硬边界（代码层已钉死，有测试）**：`ingestAppendBlock` / `ingestRemoveBlock` 严格对称 ——
  追加后撤销可**字节复原**；撤销只摘本组锚点区间，**后来追加的年轮原样保留**；锚点被人工编辑破坏时
  返回 `INGEST_ANCHOR_LOST` 转人工，**绝不盲删**。

### ✅ B13 媒体元信息完整化（音视频探测 ffprobe + 匿名公开出口，已完成 2026-09-23）

> 背景：B8 把媒体底座的**表结构与只读链路**落定了，但音视频探测被搁置为
> `probe_status='unsupported'`（当时服务器无 ffmpeg）。本批把这块补齐 —— 属"能力补全"，**不动 schema**。

- **探测能力**（`service.ProbeAV`）：调 ffprobe 取时长/宽高/编码/码率并解析其 JSON 输出。
  - 🔴 `duration` 与 `bit_rate` 在 ffprobe 输出里是**字符串**（且可能为 `"N/A"`）——
    声明成数字会让整个 Unmarshal 失败（表现为"所有视频都探测失败"），是最容易踩的坑（§7 坑 34）。
  - 参数走 args 数组、路径不参与 shell 拼接 → **无命令注入面**；5s 超时防坏文件挂死请求。
- **只在本地磁盘后端可用**（`storage.PathLocator` 可选接口）：mp4 的 moov 原子可能在文件尾，
  必须**就地随机访问**，拿 `io.Reader` 顺序读不可靠。S3/WebDAV 等远程后端不实现该接口 →
  `FileStore.LocalPath` 返回 false，调用方**安静降级**为 `unsupported`，**不把整个对象拉回本地**
  （音视频动辄数百 MB，代价远大于"这次探测不到"）。
- **`unsupported` 不是终态**（关键设计）：缓存命中条件**有意排除** `pending` 与 `unsupported`，
  否则装好 ffmpeg 后旧记录会永远停在 `unsupported` —— 这对"能力可降级"的承诺是致命的。
  重探成本极低：无 ffprobe 时只做一次 `exec.LookPath`（微秒级，不碰文件 IO）。
- **匿名公开出口** `GET /api/v1/public/media/{id}/info`：访客可读。
  主题/第三方展示视频时长必须有它 —— `/files/{id}/media` 在鉴权中间件内，访客读不到。
  响应只回展示所需字段，**不暴露 `thumbnail_ref` / `transcoded_ref`** 等内部引用。
- **公开媒体字节端点放开到 image|video|audio 并支持 `Range`**（交 `http.ServeContent`）：
  此前只服务 image，公开页的视频**根本播不了**；现在可 `<video>` 播放、可拖动进度。
  （本地后端返回 `*os.File`，天然 `io.ReadSeeker`；流式后端退化为整段输出。）
- 运维：服务器 `apt-get install -y ffmpeg`（7.1.5）。⚠️ 该机 nginx 为自定义配置，
  **必须带 `--force-confold`**，否则 dpkg 卡在 conffile 交互上（§7 坑 33）。

2. **行尾不统一**：`repo/schema.go` / `public_blog_ai.go` / 前端 = CRLF；`routes.go` / `authmw.go` = LF。改文件必须按目标文件行尾写回。
3. **`Edit` 工具在本仓库会静默吞改动**（多次复现）→ 关键改动一律用 Python 落盘 + 事后 grep 复核。
4. **匿名端点要改两处**：`routes.go` 注册 + `authmw.publicPath` 白名单，漏了白名单会出现"登录才可用"的假故障。
5. **新的列表/聚合端点必须带站点隔离**（`currentSiteID(r)`），否则多站点下会跨站串数据。
6. **面向用户的实体 id 用 `newID()`**，不用 `google/uuid`（上游 `collab` / `issues` 用了 uuid，属移植时需替换项；本批不涉及）。
7. **表 DDL 统一加到 `repo/schema.go`**（本壳 40 表 → B1 41 → B2 43），幂等 `IF NOT EXISTS`，随启动迁移。
8. **本壳裁剪过上游表**：`workflow_defs` 在 schema 里被注释为「已裁剪」（DDL 不在）——移植上游模块前**先确认表在不在**，
   否则会「编译通过、运行报 no such table」。B2 已按上游同构恢复该表。
9. **本壳 `ai.Gateway` 没有 `Ask`**（上游有）：一律用 `ChatJSON`，并注意**未配置模型时它返回降级文案而不是 error**
   （会静默把提示语当内容写出去）。
10. **e2e 隔离：storage 根跟随进程 CWD**（`storage.local.root` 默认 `./data/files`）。在服务器上起临时实例做端到端时，
    `cd <独立目录>` 之后**必须回查 `/proc/<pid>/cwd` 确认**，否则测试文件会落进生产 storage 根。
    生产由 `start_aiklog.sh` 的 `cd /opt/aiklog` 保障 → 实际存储根 = `/opt/aiklog/data/files`（备份要备这里）。
11. **IM 指令前缀是稀缺资源**：新增任何「斜杠命令」前先查 `im/intent.go` 的 `prefix` 表，
    否则会静默抢键（map 遍历无序，"谁赢"不确定）。
12. **`files.created_at` / `updated_at` 是毫秒**（`publish_at` 也是毫秒）：按秒解释会得到 58681 年。
    写查询/脚本时一律 `/1000` 再格式化。
13. **对外公布的 feed / sitemap 地址不是 `/blog/feed.xml`**：SSR 页里 `<link rel="alternate">`
    写的是 `/api/v1/blog/feed.xml`（实测 200）；`/blog/feed.xml`、`/feed.xml`、`/sitemap.xml` 一律 404。
    验证对外订阅/收录时，**以页面里公布的地址为准**，别按常规约定猜。
14. **`/api/v1/public/link-check` 未列入匿名白名单**（`authmw.publicPath`），虽名为 `public/` 但需登录。
    属既有不一致，本批未动；如要匿名可用，补一条 case 即可（改前先确认它是给谁用的）。

15. 🔴 **存储根随「可执行文件位置」，不随进程 CWD**（B3 本轮踩出**生产事故**，旧记录是错的）。
    `main.go`：`root := cfg.GetString("storage.local.root")`（缺省 `./data/files`），
    若**非绝对路径**则按 `dir(exe)/../<root>` 解析 —— 目的是防「不同启动方式把数据写散」。
    后果：把测试二进制放到 `/opt/aiklog/bin/` 下起「隔离」实例，storage 仍指**生产根**，
    端到端测试会**原地改写生产文章**（文件数不变，所以仅比数量发现不了）。
    正确姿势：沙箱内建 `bin/`，二进制放 `<沙箱>/bin/<name>`（则 `dir(exe)/..` = 沙箱根）；
    并在起进程后**回查 `/proc/<pid>/exe`**（而不是 CWD）确认落在沙箱内。
16. **e2e 收尾校验必须比「内容哈希清单」**：`find <root> -type f -exec sha256sum {} + | sort | sha256sum`，
    再直接 `grep -rl <测试痕迹> <root>`。只比文件数对「原地改写」是瞎的（本轮即因此漏检）。
17. **隔离失败的善后判据**：若只有 storage 被污染、DB 未被改（`-db` 是显式参数，所以副本库隔离是真的），
    则生产 DB 里 `files.sha256 / size / version` **仍是原始值** → 清除污染后可与 DB 记录做**字节级校验复原**
    （B3 本轮即用此法复原，`RESULT=MATCH`）。污染文件备份在 `/root/b3_incident_backup/`。

18. 🔴 **Go 的 RE2 正则不支持 `\u` 转义**（B5 踩出，会直接炸启动）：`regexp.MustCompile("^[\u4e00-\u9fa5]+$")`
    在 `go test` 阶段即 panic `invalid escape sequence: \u`，二进制一启动就崩。**正确写法 = 反引号原始字符串 + `\x{...}`**：
    ```go
    var varNameRe = regexp.MustCompile(`^[\w\x{4e00}-\x{9fa5}]{1,64}$`)
    ```
    注意 `\w` 在 Go 里**已含下划线与 ASCII 字母数字**，但**不含中文**，中文字符必须显式写 `\x{4e00}-\x{9fa5}`。
    凡是要匹配中文的正则（变量名、标签、条目名），一律照此办理。
19. **`go fmt` 会把 CRLF 文件整篇改写成 LF**：对 `service/file.go`（CRLF）跑一次 `go fmt`，
    整文件变 LF、产生几千行噪音 diff。**本仓库禁跑 `go fmt ./...`**；单文件如需格式化，
    事后用 Python 把 `\n` 还原成 `\r\n`，并复核补丁内容是否完整。
20. **移植上游模块前先读「上游自己的实现完整性」**（B5 的教训是双向的）：
    `file_versions` 上游有完整实现但**有幽灵版本缺陷**（`RestoreVersion` 只写 DB 不落快照 → 列出的版本下载 404）；
    `prompt_templates` 上游**只建表、零实现**。所以「上游有」不等于「照抄即可」，
    要逐函数看它有没有把「登记」和「落盘」成对做完。本批两条都已修（见 §5.7.五）。

21. 🔴 **构建树有自己的 `webdist` 副本**（B6 部署踩出，症状极隐蔽）：服务器上的 Go 构建目录
    （`/root/b4build/srv/server`）里 `internal/handler/webdist` 是**独立一份**，与
    `/opt/aiklog/src/server/...` 的那份互不相干。只更新后者就 `go build`，二进制里嵌的仍是**旧 SPA**：
    旧 assets 照旧 200 取到、新 assets 返回 639 字节的 SPA 兜底 HTML（**不是** 404，所以按状态码验会被骗过）。
    判据必须比**内容哈希**：`curl /assets/<新hash>.js | md5sum` 对齐 `dist/assets/<新hash>.js`。
    修法：两份 webdist 都覆盖后再编译。
22. **不要对被写成 BLOB 的 TEXT 列用 `LIKE` / `GLOB`**（B6 踩出）：`notifications.payload` 列声明 TEXT，
    但早期代码绑了 `[]byte`，驱动按 BLOB 落库 → `LIKE '%x%'` 恒返回 0，去重逻辑静默失效。
    规避：① 写入端统一绑 `string`；② 查询端用 `instr(col, ?) > 0`（对 BLOB / TEXT 都成立，兼容历史行）；
    ③ 排查时先 `select typeof(col)` 看真实存储类，别只看 DDL。
23. **`pkill -f "<端口/路径片段>"` 会连自己的 ssh 会话一起杀**（B6 踩出）：远端命令的**命令行本身**
    就包含那个片段，`pkill -f` 匹配到 `bash -c ...` 会把父 shell 一起干掉 —— 表现为
    「ssh 输出戛然而止、后半段命令没执行、只看到前半截」。
    对策：把清理动作写成**脚本文件**再 `sh /path/cleanup.sh`（脚本的命令行不含该片段），
    或 `pgrep` 先取 PID 再 `kill <PID>`。

24. 🔴 **`_tmp` / `*_ref` 抓取件 ≠ 上游实物**（B7/B8/B9 连续三次踩出）：本仓 `aikmap_cn_ref/_tmp/schema.go`
    这类"参考资料"里的表名（`im_bindings` / `skill_packages` / `media.go` 等）在上游真实仓库里**根本不存在**。
    照它开工 = 按错误清单"移植"一个没有的东西。**铁律**：任何"上游有 X"的判断，必须回上游真实
    `server/internal/repo/schema.go` 等处核对；抓取件只能当线索，不能当证据。
25. 🔴 **写 DDL 的 Go 反引号 raw string 里不能再出现反引号**（B7 踩出，会直接编译失败）：
    `schema.go` 的 DDL 是 `` `CREATE TABLE ...` `` 一整个 raw string，注释里写
    `` `/bind <码>` ``（带反引号）会**提前截断字符串** → 报 `undefined: bind` / `undefined: 码`。
    **规范**：DDL 注释里提到命令一律不加反引号（写 `/bind <码>`）。
26. **时间戳单位混用是本壳的结构性债务**（B7 再次踩出，且已造成真实缺陷）：`files.*_at` 是**毫秒**，
    `doc_subscriptions.created_at` / `im_ingest.created_at` 是**秒**，B7 新表统一毫秒但 `used_at` 用 `0` 当"未使用"哨兵
    （不依赖 NULL）。**写任何跨表时间比较前，先看两边单位**——`digest.go` 的"今日入库"就是
    毫秒值被拿秒阈值比（恒真）而坏了很久（§5.9.五）。
27. **e2e 断言里的"当前时间"别用 SQLite `strftime('%s','now')`**：它只到**秒**，
    `*1000` 后最多**低估 999 ms**，会让"TTL 正好 600s"这类边界断言**假失败**（本轮实测差 600255 ms）。
    用 `int(time.time()*1000)`（Python）或 Go 侧同源时钟。另：**webhook 类端点的响应不含回复正文**
    （`im` 回调只回 `{"ok":true,"handled":reply.OK}`），要断言"被拒"就查 `handled==false` + **库内状态未变**，
    不要去找回复文字。

28. 🔴 **`@[显示名](user_id)` 是合法 Markdown 语法，不接管就会渲染成死链**（B12 踩出）：
    默认解析器把 `@[张三](abcd…–…ab)` 渲染成 `<a href="abcd…">张三</a>` —— 一条**指向 user_id 的死链**
    （相对路径，点了 404），而且**不报错、不进 console**，只看构建产物毫无异常。
    要接管必须注册自定义 `parser.InlineParser`（`@` 触发）+ `renderer.WithNodeRenderers`，
    且**优先级要给到 500**（高于默认链接解析器），否则仍会被链接解析器抢先。
29. **纯写法 `@用户名` 必须做前界检查**（B12 踩出）：`someone@example.com` 的域名同样匹配
    `@([\p{L}\p{N}_.\-]{1,32})`。RE2 没有 lookbehind，别指望正则解决 ——
    用 `text.Reader.PrecendingCharacter()` 看前一个字符（字母/数字/`_ . - +` 则不算提及）。
    前端 marked 侧拿不到前一个字符（tokenizer 只收到从 `@` 起的剩余串）→ 前界检查要放在 `start()` 里。
    **且渲染规则必须与 `service/mention.go` 的解析正则逐字一致**，否则会出现「高亮了却没通知」的错配。
30. **SSR 页不渲染评论 → 归因回指链接停在页首**（B12 闭合）：`{origin}/{slug}#comment-{id}` 的落点
    必须有元素真带 `id="comment-{id}"`。修法是让内置模板输出评论列表；⚠️ 评论是**访客可写内容**，
    SSR 侧一律**纯文本 + 自动转义**（换行交给 `white-space:pre-wrap`），**不要**在服务端再跑一次
    Markdown 渲染 —— 多一层解析就多一层 XSS 面。
31. 🔴 **`/opt/aiklog/src/server` 与构建树早已严重分歧（B12 发现）**：它缺 B6–B9 的
    `mention.go`/`subscription.go`/`skill.go`/`media.go`/`im_binding.go`，`shares.go` 里连
    `collectBlogArticles` 都没有 —— **它自己根本编译不过**。所以 `src/server_bak_<ts>` 只是历史快照，
    **唯一可信回滚点是 `bin/aiklog.bak.<ts>` + `data/aikmap.db.bak.<ts>`**；
    判断「线上跑的是哪份源码」一律以构建树 `/root/b4build/srv/server` 为准。
32. **验证「嵌入的 SPA 是不是新版本」不能看状态码**：新旧 assets 都返回 200 ——
    旧 hash 返回的是 639 字节的 SPA 兜底 HTML。判据 = `Content-Type` + `Content-Length` + 内容哈希，
33. 🔴 **在「nginx 是自定义配置」的机器上跑 apt 必须带 `--force-confold`**（B13 踩出，代价：三个包卡在 `iU`）：
    `apt-get install ffmpeg` 顺带升级 `nginx-common` 时，`/etc/init.d/nginx` 与包内新版冲突，
    而 dpkg 在 `DEBIAN_FRONTEND=noninteractive` 下**无法提问** → 退出码 100，
    `nginx` / `nginx-common` / `python3-certbot-nginx` 停在 `iU`（已解包未配置）。
    ⚠️ **nginx 是生产 Web 服务器，这个状态必须收尾**（否则后续 apt 操作全线失败）。
    **修法**：先 `cp -a /etc/init.d/nginx <备份>`，再 `dpkg --force-confold --configure -a`
    （保留本地配置、非交互完成）。**判据**：`dpkg -l | awk '$1!="ii" && $1!="rc"'` 为空 +
    `nginx -t` OK + `pgrep -c nginx` 有值。本次修复**没有重启 nginx**
    （postinst 见端口 80 被占即跳过启动），服务零中断。**预防**：此类机器上 apt 统一加
    `-o Dpkg::Options::=--force-confold`。
34. **ffprobe 的 `duration` / `bit_rate` 在 JSON 里是字符串**（B13 踩出）：`"duration":"1.000000"`、
    `"bit_rate":"58840"`，且可能为 `"N/A"`。结构体里声明成 `float64` / `int64` 会让**整个 Unmarshal 失败**
    （返回零值 + error，表现为"所有视频都探测失败"）。必须按字符串接收再做容错转换。
    另：纯音频没有 video 流，`width` / `height` 应保持 0 —— 判类型请看 **mime / `kind`**，不要看宽高
    （否则音频会被当视频渲染成 0x0 黑框）。

35. 🔴 **「总开关」可能只是个名字，没有实现**（B14 踩出）：`service.OrgStore.Enabled()` 方法存在、
    `org.enabled` 配置项也在文档里写着"关闭后组织端点一律 403"，但 **handler 层一处都没调用它** ——
    组织树的建/改/删在总开关关闭时**仍能正常写库**（e2e 真建出了一个节点才发现）。
    **教训**：给任何"总开关/子开关"做面板之前，先 `grep` 该判定函数在 handler 里的**实际调用点数量**；
    "定义 + 描述"不等于"上了闸"，只有被调用才算。反过来说，**门控类改动必须用"关闭态逐端点断言"来验证**，
    只在单测里查白名单会放过这种洞。
36. **清空配置项 ≠ 删除配置行**：`config.Store.Set(ctx, key, "", ...)` 是 `INSERT ... ON CONFLICT DO UPDATE`
    写一行 `value=''`，**不是 DELETE**；`explicit[key]` 仍为 true、内存值也是空串。
    判定侧只要把"空串"当"未配置"就完全等价（本项目 `capability.*` / `org.*` 都是这个口径），

37. **给端点补门控会连带打出"误导性报错"**：后端加了 403，前端原有的"加载失败"toast 就会在

39. **`watch(source)` 在"创建时"就会求值一次源**（与 `immediate` 无关）→ 在 setup 期监听一个

40. **`Page.navigate` 到"只有 hash 不同"的 URL 不会重新加载页面**（同文档导航）→
    靠 `localStorage` 初始化的 store **不会重读**。本次浏览器脚本用

41. **前端校验脚本不要写死构建产物的入口 hash**（`index-<hash>.js` 每次构建都变，会稳定假失败）。

    另：线上资产**必须比内容哈希**，不能看状态码 —— 不存在的 `/assets/*.js` 会返 **639 B 兜底 HTML 且 200**。

42. 🔴 **SPA 真入口不能靠 `ls assets/index-*.js | head -1` 猜**（B16 踩出）：`dist/assets/` 下同时存在
    多个 `index-*.js`（本次 1567 B 的小 chunk 与 180 KB 的 `index-DxYNjKY-.js` 并存）。

    → 再断言 entry 内含新端点字符串（如 `admin/derived/stats`）。
43. **CRLF 的 `.go` 文件本就不过 `gofmt -l`**（B16 复核）：本壳 `config.go` 等 CRLF 文件、
