### R2 · 能力开关（capability gate）宿主契约 —— ⚠️ 需对齐，采纳拟实现

主系统现状：开关宿主 = `blog_plugins` 表（`kind='capacity'` + `capabilities` 字段 + `enabled` 列，manifest 已有 `Enabled *bool`）；装配期由 main 按 CoreModules 静态注入，**暂无"安装→运行时点亮字段"的动态表**。
**对齐结论**：采纳 AiKlog 拟实现为统一口径——安装 capacity 应用写一条 `blog_plugins` 记录（kind=capacity, capabilities=[...], enabled=1）；停用/卸载置 `enabled=0`（或删除记录）；main 装配阶段查已启用 capacity 记录决定是否构造对应 Store 注入 CoreModules；停用字段传 nil → 路由不注册 404。双方按此实现，避免单壳差异化。

### R3 · 配置包（源包）格式规范 —— ❌ 待补（主系统当前无现成 schema）

主系统 sources 表实战字段（`repo/schema.go` sources 建表 + `service/source.go` SourceConfig）：`kind` / `channel_type` / `template.list.urls` / `direct_items` / `target_dir` / `city_whitelist` / `fetch_mode` 等——**但"配置包 zip"格式（字段定义/校验/版本/合规声明）尚未成文**。
上游将出《采集源包格式规范 v1》（建议内容：包内 manifest.json 复用 pluginManifest 骨架 + `sources[]` 数组（每个源一条 template）+ 合规声明字段（target_site/usage）+ 校验规则 + 落地位置建议=导入写 sources 表，zip 归档于 market/official/）。**本期先给规范文档，实现随 R5/R6 同步包一起给**。

### R4 · 平台令牌（service token）签发契约 —— ✅ 已实现，给契约

主系统：配置键 `security.service_token`（config.go:127，env 注入 `AIKMAP_SERVICE_TOKEN`，main.go:69-70）；`authmw.go:139/175` 服务令牌白名单（读列表/写文档/建目录/删/改正文/读正文；留空=停用）。
**契约**：service token 即一个高权限 Bearer 令牌（全量白名单），直接用于连接器/外部服务调内核 API；scope 粒度当前为"全量白名单"（无细分 scope 枚举）；轮换=改配置重启（或重写 env 重启）。如需细分 scopes（如 `collect:run` 专用），属待扩项，可与 R7 Entitlement scopes 一并规划。

### R5 · collect API 面 + collector.finished —— ✅ 已实现

- `POST /api/v1/collect/run`（source.go:65）：`{city, source_ids?, limit?, force?}` → 立即返回 `run_id`，异步逐源抓取入库
- `GET /api/v1/collect/runs?city=&limit=`（source.go:94）：查询 run 状态/结果（RunStatus/ListRuns，service/source.go:335/348）
- `collector.finished {run_id, status, created, failed}`：`engine/bus/topics.go:24` 内核冻结 topic，采集完成经事件总线发布

### R6 · 事件契约 v1 落地（订阅白名单 + publish 权限） —— ✅ 已实现

`engine/bus/topics.go`：`KernelTopics` 冻结清单（file.*/tag.*/config.changed/impex.*/vector.indexed/collector.finished）+ `ValidateTopic(topic, pluginID)`（内核清单或 `{plugin_id}.{event}` 自有命名空间）；插件声明 hooks.subscribe/publish 必须命中。最小同步 = 移植 `engine/bus/topics.go` + hooks 校验（blog_plugins.go pluginHooks）。

### R7 · 计费与授权口径 —— ✅ 机制就绪，扩 scope 即可

主系统 `entitle/entitle.go`：License（ed25519 签名）+ `Scopes []string`（含 `all` / `shell:<id>` / `HasFeature(name)` 自由匹配）+ `IsPro(shellID)`。**`capability:*` scope 可直接纳入**（scopes 为自由字符串，签发端加即可）；源包商品结算（买断/订阅/更新订阅）属结算 v0.3 范围，建议与 R10 一起定。

### R8 · 采集审核与合规边界 —— ⚠️ 需出边界文档

主系统已内置：SSRF 防护（`ssrf.go`，采集模块自带同类防护）。需补的边界文档项（建议出《采集商品上架审核规范 v1》）：SSRF 白名单复核、抓取频率上限、robots 遵从、版权/来源声明字段（源包合规声明）、**责任边界**（建议：内容合规由源包作者承担，平台负审核与下架责任——与协议 §6"内核只负责令牌与开关"一致）。

### R9 · L2.5 第三方采集器部署形态 —— ✅ 形态即 service token + collect API

主系统当前形态 = **外部服务 + service token（R4）+ collect API（R5）**：第三方采集引擎部署为独立服务，持 service token 调 `POST /collect/run` / `GET /collect/runs` 驱动内核采集；注册/鉴权即 service token 白名单。无需新增机制。

qiuzhi（一源多城、kind 分流、探路建源）经验可沉淀为官方源包；官方源包上架 + 壳侧代销分成口径待结算 v0.3 排期时一并定。

### R11 · capacity 应用 UI 承载 —— ✅ 采纳回贡方案
